# 规范 · 设置抽屉与帮助分工（现行）

> 现行规则见 [决策 010](../decisions/010-standalone-exe-and-settings.md)、
> [决策 011](../decisions/011-unified-help-and-manual-update.md) 与 [决策 014](../decisions/014-workbench-ui.md)。
> 2026-11-03 UI-B 起，顶栏分成「设置」「帮助」两个入口，取代旧的「单一帮助面板含版本、数据和条款」。
> 本页按实际实现写；旧版「统一帮助与手动检查更新」规范已被取代，历史见 git。
> 代码以 `local/ui/index.html`（`aside#settings`、`dialog#help`）、`local/ui/views/settings.js`、
> `local/ui/views/help.js`、`local/ui/views/update.js`、`local/ui/views/phone.js` 为准；
> 接口与更新七态以 `docs/UI_SPEC.md` §5.1、§5.18 为准。

## 1. 两个入口怎么分

| 入口 | 形态 | 放什么 |
|---|---|---|
| 设置（`#btn-settings`，齿轮图标 + 文字，可访问名称「设置：高级功能、登录、程序」） | 右侧抽屉 `aside#settings`（非模态，宽 `min(32rem, 100vw)`） | 会改东西的项：高级功能、保存的账号、关闭窗口时、版本与更新、本机数据、条款同意与撤回 |
| 帮助（`#btn-help`，问号图标 + 文字，可访问名称「帮助：使用说明、快捷键、重看引导、查看条款」） | 对话框 `dialog#help` | 只讲怎么用：三步使用说明、键盘快捷键、重看引导、查看条款（只读） |

中档和窄档（宽 < 1040）顶栏按钮只留图标，文字仍在可访问名称里。两处都不放未确认的功能
（例如「清空凭证」「重置」「自动更新」「自动检查更新」），契约测试钉住。

## 2. 设置抽屉

- 头部：标题「设置」+ 关闭按钮 `#btn-settings-close`。
- 分组跳转：头部下方三个按钮「高级功能 / 登录 / 程序」（`data-sec="adv" / "login" / "prog"`），
  点了滚到对应分组标题 `#set-adv` / `#set-login` / `#set-prog`（标题带 `scroll-margin-top`，不被吸顶导航挡住）。
  开始前提醒里的「去保存」「去安装」用 `openSettingsSection()` 直接打开到对应分组。
- 正文一个滚动区，三组从上到下排列；最底部一行 `#help-status` 放局部反馈（例如撤回结果）。
- Esc 逐层关闭：先关详情卡，再关对话框，最后关设置抽屉；关闭后焦点回顶栏「设置」。

### 2.1 高级功能（`#set-adv`，可选，用到时点一下就装）

| 行 | 内容 |
|---|---|
| 跨设备访问 · 手机控制 | 未安装时「安装手机控制」；装好后选远程通道（Tailscale / Cloudflare 临时地址）、开启 / 关闭访问（关闭要确认）、地址、二维码、配对码。细节见 `docs/PHONE_ACCESS.md` |
| 验证码识别 | 未安装时标题行右侧「下载并安装」（`#btn-ocr-download`），下载中可「取消」；只有下载失败、组件加载失败或被停用时才露出「导入已下载的组件包」作为后备，导入仍当场自检 |

### 2.2 登录（`#set-login`，保存的账号与失效后自动登录）

一张「电脑续登录」卡片 `#relogin-card`：
- 逐行写：验证码识别是否可用、账号是否保存（**只显示打码**，前两位加后两位）、最近一次登录、
  电脑上能不能自动恢复、手机上重新登录要什么。保存的密码被学校拒绝过时写明「自动登录已暂停」。
- 动作：「填写账号密码」展开输入并「保存到本机」；「清除已保存」先展开确认（写明清除后电脑不再自动恢复、
  手机重新登录要重新输入），确认才清除。

### 2.3 程序（`#set-prog`）

| 行 | 内容 |
|---|---|
| 关闭窗口时 | 下拉 `#close-pref`：每次询问 / 最小化 / 隐藏到后台 / 直接退出，写 `ui.json` 的 `window.close_action`；计划运行中选了「直接退出」仍会先问一次 |
| 版本与更新 | 标题行写当前版本；推进按钮固定在标题行右侧，每一步只留一个推进动作（下载并安装 / 确认下载 / 启动安装程序 / 取消 / 关闭本工具…），流程按钮出现时收起「检查更新」；状态自己变化后新按钮先停 0.8 秒防误点；计划运行中校验通过改叫「仍然启动安装程序」；「前往下载页」只打开固定发布页。七态与文案见 `docs/UI_SPEC.md` §5.18 |
| 本机数据 | 说明「登录信息、工具设置和运行记录保存在这台电脑。」+「打开数据目录」 |
| 使用条款与隐私 | 当前条款版本和同意状态（「你在 … 同意了这一版。」或「还没有同意这一版：…都已停用。」）；「查看条款」（`#btn-help-terms`）；「撤回同意」（`#btn-terms-withdraw`） |

**撤回同意**：
- 只在已同意当前版时显示；计划运行中按钮禁用，悬停提示「计划运行中不能撤回，先停止计划」。
- 点了先在这一行下方展开确认区 `#terms-withdraw-confirm`，写明撤回后登录、登录检查、自动登录、刷新活动和
  开始计划都会停用，保存的账号密码和登录信息不会删除；点「确认撤回」才调 `withdraw_terms()`。
- 后端在计划运行或已就绪时同样拒绝（`plan_running`），零写入；成功回执带条款快照，界面按它立刻关上条款门。

## 3. 帮助

`dialog#help`，标题「使用帮助」，副标题「使用说明、快捷键、重看引导与条款」：

1. **三步使用说明**（`#help-steps`，与 `Api.help` / 前端 `DEFAULT_HELP` 逐字段一致），标题行右侧「重看引导」
   （`#btn-help-tour`）。计划运行中「重看引导」禁用，按钮文字改「计划结束后可重看引导」。
2. **键盘快捷键**：F5 刷新登录状态和活动列表；Ctrl+F 跳到搜索框；Esc 逐层关闭（详情卡 → 对话框 → 设置）；Enter 在焦点不在输入框时开始报名计划。
3. **使用条款与隐私**：只放「查看条款」（`#btn-help-terms-view`），同意记录和撤回在「设置 → 程序」。
4. 底部「Esc 关闭」+「关闭」。

## 4. 两处查看条款的焦点归还

两个入口打开的是同一个 `#dlg-terms`；已同意同版时是**只读查看**，只有「关闭」，不写同意时间、不记拒绝、不刷新学校数据。
- 从帮助打开（来源 `help`）：打开前先关帮助（不叠两个模态），关闭后重开帮助并把焦点交回 `#btn-help-terms-view`。
- 从设置打开（来源 `settings`）：设置抽屉不是模态，一直开着；关闭后焦点回 `#btn-help-terms`，**不弹出帮助**。
