## 一、用户、任务与范围

对象是拿到本机工具的校园同学。打开软件后，先看懂工具用途、学校访问与本机数据，再自行决定
是否同意；以后能从「设置 → 条款与隐私」找到同一份条款。界面必须让「阅读」「暂不使用」「同意并保存」各有清楚
位置，保存结果要准确。

覆盖：条款三件套（`#dlg-terms` 全文阅读器、`#dlg-terms-intro` 首次说明框、
`#dlg-terms-update` 条款更新框）、未同意/状态未知横幅、设置里的条款行与撤回确认，
以及这些入口的焦点、键盘、加载与错误状态。主界面、大屏、活动表格与停止确认沿用现状。

## 二、设计方向与方案比较

采用「站务告知单」：标题延续既有站牌深色与琥珀短线，正文是安静、易读的白色告知纸。
只在标题保留一个视觉识别点；条款正文不加点阵、渐变、装饰图或连续卡片。

```text
方案 A：要点下方不断追加全文（弃）
┌ 标题 ─────────────────────┐
│ 五项要点                    │
│ 展开后按两个标签页排两份全文 │
│ 状态、按钮随整页向下移动     │
└────────────────────────────┘

方案 B：同一阅读区切换内容（采用）
┌ 深色标题                 × ┐
│ 要点             查看完整条款│
├────────────────────────────┤
│ 状态·双版本行 与 Esc 提示   │
│ 五项并列要点 或 两份全文     │  仅此处滚动（非空反馈随区内回顶）
├────────────────────────────┤
│ 暂不使用      我已阅读并同意 │
└────────────────────────────┘
```

方案 A 让用户在长文后寻找按钮，也把并列事项误画成操作步骤；方案 B 保持阅读位置与决策操作稳定。
自审结论：初稿的五个数字、五张卡片与「大锁」图标已取消——不表达真实顺序，且把自主同意画成
安全认证。保留站牌标题与工具一致，正文以阅读为重。**历史说明**：2026-11-08 起界面按三件套
拆开（§四），上图「要点⇄全文」只记录当时的取舍，不是现行结构。

## 四、结构与线框（`local/ui/index.html`）

`#dlg-terms` 继续用原生 dialog。2026-11-08（计划 `20261108-c3-dialogs`，决策第 1 条）起，
条款界面拆成**三件套**，同一时刻最多一个 `<dialog>` 打开；阅读器仍为三层 DOM，两个小框
各用固定头尾＋单一滚动正文。

1. **全文阅读器** `#dlg-terms`（`dialog.dlg.dlg-terms.tdoc`）：宽 `min(960px, 100vw - 32px)`、
   高 `min(736px, 100vh - 32px)`。深色点阵标题栏 h2 `#dlg-terms-title[tabindex="-1"]`
   「使用条款与隐私」＋右上 ×（`aria-label`「关闭条款」，走 `<form method="dialog">` 原生关闭，
   由 close 监听统一收口）。正文顺序：`.terms-feedback`（`#dlg-terms-status` 与
   `#btn-terms-recheck`「重新确认状态」，非空反馈回顶不移焦点）→ `p#dlg-terms-sub`
   （程序要求版本、本份副本版本与当前同意状态）→ 页签行「用户协议 / 隐私政策 / 开源许可」
   ＋右侧注「标着“本版新增”的是这次的改动」→ 宽档左侧章节导航 `#terms-toc`（11rem 常显，
   ≤719px 收起）与 `#dlg-terms-full-text` 全文阅读区。脚部：同意态为勾选
   「我已阅读并同意《用户协议》和《隐私政策》」＋「暂不使用」＋「同意并继续」；只读态为
   「关闭」；Esc 提示在阅读区尾部，同意态写「Esc 关闭」、保存中写「正在保存…」。
2. **首次说明框** `#dlg-terms-intro`（`dialog.dlg.dlg-terms-intro`，宽 38rem）：深色标题栏
   h2「开始前先了解这些」＋副题「同意后才能登录、查看活动和开始报名计划」，无 ×；正文六条
   `.pts`（标题＋说明；末条「完整条款」带「现在就看」链接钮，打开全文前先收起本框）；脚部
   勾选框居左＋「暂不使用」（线框）｜「同意并继续」（实心，勾选前禁用）。
3. **条款更新框** `#dlg-terms-update`（`dialog.dlg.dlg-tu`，宽 32rem）：深色标题栏
   h2「使用条款更新了」＋副题「新版 X，你之前同意的是 Y。同意新版后才能继续登录和报名。」
   （X/Y 读真实版本），无 ×；正文「这次主要改了：」＋变更清单（每条「新增」徽章）＋注句
   「不同意也可以继续用帮助和设置，但登录、自动登录、活动列表和报名计划会停用。已保存的
   账号密码和登录信息不会删除。」；脚部「看完整条款」｜弹性空隙｜「暂不同意」（线框）｜
   「同意新版条款」（实心，打开时焦点落此）。

### 三件套的打开时机

`openTerms()` 按本机同意状态路由（`controllers/terms.js`），横幅、设置、自动强弹共用同一入口：

| 本机状态 | 打开的面 | 说明 |
|---|---|---|
| 从未同意（有版本、`accepted_version` 为空） | 首次说明框 | 首启且本版本未拒绝过时自动强弹；勾选后「同意并继续」 |
| 同意过旧版（`accepted_version` 非空且 ≠ 当前版） | 条款更新框 | 焦点直接落「同意新版条款」，无勾选门 |
| 状态未知 / 没有版本依据 | 全文阅读器（同意态） | fail closed；不自动强弹，用户从横幅或设置打开；全文仍可读，同意按当前程序版本记录 |
| 已同意当前版（只读查看） | 全文阅读器（只读） | 只有「关闭」，零写入、零学校加载 |

两个小框里点「现在就看」/「看完整条款」：先收起小框，再开全文；两框不叠层。

### × 与 Esc 语义

- **阅读器**：右上 × 与 Esc 都是「关闭」。从两个小框进来时，关闭后**回到原来的小框**，
  不等于拒绝；直接打开（横幅、设置、自动）时关闭即离开，不记拒绝。
- **首次说明框**：无 ×；Esc＝「暂不使用」，走拒绝路径（`terms_declined_version` 落盘）。
- **条款更新框**：无 ×；Esc＝「暂不同意」，同拒绝路径。
- 保存中（「正在保存…」）三个面都拦下 Esc 与 ×，按钮禁用；超时未确认时关闭只离开待确认
  界面，不记拒绝，门禁保持。

不增加预勾选复选框、强制滚到底、倒计时或默认焦点落在同意按钮；阅读器首次焦点放可聚焦标题，
更新框焦点放「同意新版条款」。旧「要点⇄全文切换」、`#terms-toolbar`、`#terms-summary`
与 `#terms-update` 内嵌区块已删除，不并入现行结构。

### 完整条款的逐字一致契约（2026-10-28，计划 20261028-terms-embedded-exact-sync）

- `.terms-document#dlg-terms-full-text` 中用户可见的规范文本（两份：用户协议 10 节、隐私政策 8 节，各自含前言）
  与只读真源 `docs/USER_AGREEMENT.md`、`docs/PRIVACY_POLICY.md` **按 pane 分别保持逐字一致**；唯一允许的差异是 HTML/Markdown
  结构标签和折叠空白。按 pane 分别精确比较，每份两道：①逐节——前言与该份各节逐节比较；
  ②全文容器——对整个比较容器的全部文本再做一次整体比较，兜住「未入正文桶的文本」与
  「文本次序漂移」两类盲区。**HTML 侧规范化只折叠空白**，不删除、不替换任何字符；
  字面 `**`、反引号与 `#` 均属于**可见文本**——用户在界面上读到的星号、反引号或井号
  若与真源不对应（或真源有而界面无），即为不一致。
- **属于精确比较范围**：汉字、标点、括注（§6.1/6.2/6.3 子标题括注）、用词、段落与条目次序，
  以及免责声明的位置——「不是法律意见」句只出现在前言，**不得出现在第 10 节正文**
  （第 10 节以「人民法院提起诉讼。」结束）。
- **排除项**：①「本份条款可离线阅读」是独立 UI 包装，位于比较容器之外，不属于条款正文；
  ②前言中「本文件是随源码分发的可审阅规范来源……」的规范来源维护说明句是已知排除
  （计划 task4 clarify 记录，内嵌前言不呈现该句）。
- 两份 docs 为唯一只读真源，当前条款版本为 **2026-11-07-r5**（r4、r5 的升版原因以 docs/USER_AGREEMENT.md 第 8 节变更记录为准）；

## 五、状态矩阵

| 状态 | 表现与动作 |
|---|---|
| 从未同意 | 首次说明框：六条要点、勾选、暂不使用｜同意并继续；学校动作停用 |
| 同意过旧版 | 条款更新框：新版/旧版、变更清单、看完整条款｜暂不同意｜同意新版条款；学校动作停用 |
| 本版已暂不使用 | 不自动再弹；顶部一条横幅与设置保留「查看条款」 |
| 条款状态未知 | 不自动弹；横幅「条款状态没能确认。」（见偏离记录），可主动阅读本份全文并确认 |
| 保存中 | 按钮「正在保存…」；一次在途调用，禁用同意/暂不使用/暂不同意与阅读器 ×，cancel 拦下原生 Esc |
| 保存失败 | 局部说明原因与「请再点一次」；恢复控件，保留阅读内容与滚动位置 |
| 保存结果未确认 | 10 秒后允许关闭；保留门禁，给「重新确认状态」，禁止直接再次写同意 |
| 版本不匹配 | 显示本份与程序要求两份版本 + 「重新下载完整版本后再确认」；零写入不解锁 |
| 已同意查看 | 只读，有「关闭」；不二次保存或加载学校数据 |
| 离线演示 | 既有 demo 豁免不变；阅读条款不使演示转成真实学校动作 |

反馈文案说用户能做什么，不展示「后端回执自相矛盾」这类实现语言；条款错误不写入报名结果、
大屏或登录过期提示。

## 六、版本绑定与保存契约（前后端两端缺一不可）

- `bootstrap.terms` = `{version, accepted_version, accepted_at}`；缺 `version` 即未知
  （fail closed）。`#dlg-terms-document-version` 是用户实际读到的副本版本，唯一节点。
- 前端 `acceptTerms` 先做本地预检（副本无版本/与程序版本不一致 → 零请求零写入），
  再调 `accept_terms(document_version)`；回执必须 `version/accepted_version/accepted_at`
  齐全、`accepted_version === version`、且与副本同版，任何一项不满足都只提示、不改状态、
  不清 unknown、不关弹窗、不刷新。
- 后端 `Api.accept_terms(document_version)` 在 `time.strftime` 与 `update_prefs` **之前**做
  严格类型+等值校验；无参、空值、非法类型或不同版本一律 `{ok:false,
  error:"terms_version_mismatch"}`，写次数为零、不起线程。prefs 锁竞争返回 `prefs_busy`
  既有语义不变。只有两端都成立，才能声称「版本不匹配没有记录同意」。
- 10 秒只表示**未收到可确认结果**，不表示事务已取消：超时使原请求代号作废
  （`requestSeq`），迟到 Promise 不关窗、不覆盖、不重复刷新。「重新确认状态」仅调用
  `bootstrap` 读条款快照（不跑 boot、不刷新学校）：同版已保存+有时间+匹配本份 → 按显式
  同意成功收口；明确未保存 → 恢复同意按钮；读取失败/对不上 → 继续保留未确认。
- 显式同意的一次成功确认最多补**一次**首轮加载（`refresh(true)`）；只读查看不补加载。
  保存中按 F5 不强拦，重载只按 bootstrap 恢复、不重提交。
- 本机桥接增量参数不改变学校 API；接受现有同意记录的规则不变。

## 七、引导、模态与键盘

- **条款先于欢迎/引导**：boot 时 `termsLocked()` → 首次欢迎与五步引导都存入
  `S.terms.deferredIntro` 延后；同意成功后只继续一次（引导适用性再判定一次）；
  拒绝后本会话不自动开引导；绝不写 `tour_version` 伪装完成；未知态不让引导覆盖提示。
- 设置入口：打开条款先关抽屉外的其他弹窗（不叠两个 open dialog）；关闭后焦点回
  `#btn-help-terms`。横幅入口关闭回被点按钮，按钮消失（同意成功）回 `#btn-help`；
  自动打开回 `#btn-help`。打开时五步引导让位（`tourPauseNow`），关闭回原步骤，
  不标完成、不改 `TOUR_VERSION`、不主动开始报名。
- document 级快捷键**第一道判断**是三个条款面任一 `<dialog>` 打开即 return（位于
  tour/搜索处理之前）：Enter/Esc/Ctrl+F/「/」/F5 不穿透背景，原生 Tab、按钮 Enter/Space
  与正常重载保持可用。保存中的 Esc 由 dialog `cancel` 明确拒绝；其余按面分流——
  首次说明框 Esc＝暂不使用，条款更新框 Esc＝暂不同意，阅读器 Esc＝关闭（从小框进来则
  回小框）。

## 八、窄窗与响应式

三层分工：dialog `overflow:hidden` + `min-width:0`（越界交给内部滚动区处理，不整页裁内容）；
`display:flex` 只加在 `.dlg-terms[open]`，保证关闭的原生 dialog 不被 CSS 显示出来；
`.terms-body` 是唯一滚动区（`flex:1 1 auto` + `min-height:0` + `min-width:0`）。
宽 `min(960px, calc(100vw - 32px))`、高 `min(736px, calc(100vh - 32px))`；两个小框
