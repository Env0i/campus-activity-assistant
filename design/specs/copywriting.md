# 规范 · 界面文案（copywriting）

> 本文件是全界面用户可见文案的**唯一现行真源**，与 `local/ui/`、`local/app.py`（Api.help）
> 的现行实现同步（2026-10-27 真实数据修复轮：签到时间段、报名回写、立即模式）。
> 基线信息量以 `docs/UI_SPEC.md` §6 为准；
> 改措辞不丢信息即可，但本页与实现冲突时以实现为准并回改本页。
> 面向使用者：拿到 EXE/ZIP 独立使用的校园同学；不要求了解开发过程、日志协议、凭证或授时细节。

## 1. 总规则

1. **中文、短句、中性工具语气**：标题说当前状态，正文只补影响和下一步；
   按钮描述点击后真正发生的动作。不用品牌口号、说教或情绪化的抢单式表述。
2. **一个动作从头到尾一个名字**：登录 →「检查登录…」→「登录成功」；停止 →「正在停止…」→「已停止」；
   预报名 →「等待开放」→「报名成功」。
3. **错误回答两件事**：发生了什么 + 现在能做什么；完整原因与醒目恢复动作只放一个负责区域，
   常驻入口（顶栏胶囊）不重复长文。
4. **说估算就写「约」**：「约剩 N 小时」「约到 xx 过期」——估算不是保证值；
   没有可信锚点时不报数字，只在详情说明「以学校校验为准」。
5. **不写技术词给主界面**：token/接口/子进程/退出码 → 登录状态 / 学校站点 / 程序组件；
   原始协议、学校原话可保留在详情与运行记录，不改解析协议来润色文案。
6. **正常状态安静显示**：顶栏时间正常只显示「北京时间 + 时分秒 + 状态图形」；
   只有需要处理的问题才带说明和恢复动作。
7. **不承诺**：报名成功、登录有效时长、时间零误差、所有数据绝不离开电脑，都不写。
8. **适用范围只放首次条款摘要**：「适用于目标学校（校园）专升本学生使用的活动中心」；
   帮助与主界面都不重复人群介绍（原型帮助里没有这段），不写开发者对话或某位用户的电脑设置
   （如「为了用 AI 改了日期」）。**现状（2026-11-08）**：帮助里的这句已删；首次说明框第 1 条
   已写「只适用于一所目标学校」。

## 3. 顶栏登录胶囊（四态 + 忙时 + 演示）

源：`local/ui/app.js` `paintLogin()`。胶囊只表达登录结论；计划进度放报名区域。

| 状态 | 胶囊主文 | 附加 | 顶栏按钮 |
|---|---|---|---|
| 从没登录过 | 未登录 | 「打开顶栏的登录状态，点「登录」，在打开的浏览器中完成登录」 | 登录 |
| 校验等待中 | 检查登录… | 「正在检查登录状态，马上就好」 | 登录 |
| 校验有效（有估算） | 已登录 | 「刚核对过，可以加载活动；预计约到 HH:MM，以学校为准」 | 重新登录 |
| 校验有效（无锚点） | 已登录 | 「刚核对过，可以加载活动」；**不编小时数** | 重新登录 |
| 明确失效（4001） | 登录已失效 | 「重新登录后可继续使用」 | 重新登录 |
| 网络未知 | 登录待确认 | 「暂时无法确认登录状态；检查网络后点「刷新」，先不用重新登录」 | 登录 |
| 忙时 | 已登录 / 未登录 | 「登录状态保持不变；计划进度见报名区域」/「正在停止计划；已报名的场次不受影响」 | 禁用 |
| 演示模式 | 演示模式 | 「内存样例」「不读取登录信息、不访问学校，只演示界面与流程」 | — |

**红线**：unknown 一律不写成「过期 / 失效」；未知小时数留空，不编「约剩 17 小时」；
忙时不拿「正在处理」替换登录结论；**预计有效只写「预计/约到 …，以学校为准」**，
不写「一定撑得到」，也不拿它放行、拦截或判过期（学校不公布有效期，估算只作提示）。

## 4. 登录动作与失败

源：`doLogin()` / `loginFailCopy()` / `handleDone`。

- 结果框成功：「登录成功」+「正在加载活动列表。」（6 秒自动收起）
- 演示模式点登录：「演示模式不登录」+「演示模式不联网。这里不会打开学校登录页。」
- 登录没能开始：「登录没能开始」+ 具体原因或「再点一次「登录」试试。」
- 窗口被关掉：「登录窗口被关掉了」+「登录还没完成，窗口就关了。点「再试一次」重新打开。」
- 等待超时：「等了 10 分钟还没登录成功」+「浏览器窗口里一直没完成登录，超时了。」
- 打不开登录页：「打不开学校的登录页」+「检查网络、校园网或代理，然后再试一次。」
- 校验未通过：「登录后学校那边没校验通过」+「登录状态存下来了，但学校那边没校验通过。再登录一次试试。」
- 缺浏览器：「没找到能用的浏览器」+「这台电脑上要有 Chrome 或 Edge，装好以后再试。」
- 其他：「登录没完成」+ 归因后的原因。

## 6. 活动模式、选择与冲突

- 模式三词不混用：未来开放「预报名」；已开放未截止「立即报名」；已截止「已截止」。
  混合计划里逐场标各自模式；「预报名」不用于已开放场次。
- 未选择：「选择要报名的活动」；可选多场举办时间不冲突的活动。
- 已报名混入：「此活动已报名，请从本次计划中移除。」——不写「先取消报名」；
  移出计划只改本机选择，不调用学校取消。
- 时间冲突：「这两场活动的举办时间重叠，只能选择其中一场」并展示活动名与时段。
- 举办时间缺失：「活动信息已变化，请刷新后重新确认」/「报名时间待公布」；
  数据异常不自动写成「尚未公布」。
- **两种「未知」必须分开**：「待公布」只表示**学校没有提供报名开放时间**
  （缺 `sign_start`）；本机暂时没有可信当前时间（校时失败/首次校准中）时，
  已知开放时间照常显示绝对日期与时刻，状态写「待校准」或「状态待确认」，
  不得整体归入「报名时间待公布」，也不得断言「没有可报名场次」。
- 组件缺失：「无法找到所需程序组件。请重新下载完整版本，再选择「重新检查」。」
  （不用「没跟着程序一起到位」这类开发对话口吻；完整说明与恢复动作只在顶部横幅）。
- 计划栏没选活动时的标签、标题、副行逐字见 §6.1（不再写「选择活动后可在此查看报名计划。」）。
- **选中不等于开始**：选择活动 = 放进计划草稿，唯一的开始动作是点「开始报名计划」；
  不写「选中后马上执行」。重新选择后回到预览，不自动开始、不重发请求。

### 6.1 计划栏：草稿（按实现写，逐字取自 `plan-panel.js`）

**空选（草稿，标签 / 标题 / 副行）**，按下表自上而下第一个命中的为准：

| 情形 | 标签 | 标题 | 副行 |
|---|---|---|---|
| 从没登录过 | 首次使用 | 登录后开始 | 活动会在登录完成后自动加载。 |
| 登录窗口等待中 | 登录中 | 正在打开登录窗口 | 在浏览器里登完再回来；中途关掉窗口会保留原来的登录状态。 |
| 条款没同意 | 已暂停 | 同意条款后才能报名 | 登录、活动列表和报名计划都停用了。帮助和设置照常可用。 |
| 条款状态没能确认 | 已暂停 | 重新确认条款后才能报名 | 登录、活动列表和报名计划暂时停用。帮助和设置照常可用。 |
| 程序组件缺失 | 不可用 | 暂时不能报名 | 程序组件缺失，处理办法在顶部提示里。 |
| 列表加载失败 | 需重试 | 活动暂时没加载 | 具体原因看左边列表的提示。 |
| 列表加载中 | 加载中 | 活动列表正在加载 | 先等这一次加载结束。 |
| 有下一场 | 下一场（已开放时「开放中」） | 活动名 | 地点与举办时间；票区下面有按钮「选这一场」 |
| 学校返回 0 场 | 暂时没有 | 学校当前没有活动 | 稍后刷新再看。 |
| 时间没校准 | 时间待校准 | 时间待校准 | 校准北京时间后才能判断哪些场次可以报名。+ 按钮「查看时间详情」 |
| 列表有活动但没有可执行目标 | 暂时没有 | 没有可报名的场次 | 列表里的活动已报名、已截止或还没公布报名时间。 |
| 其他 | 暂时没有 | 近期没有要开放的活动 | 可能还没公布报名时间，也可能都报过了。过一会儿点「刷新」看看。 |

「选这一场」只在：没选活动、有下一场、列表已加载、条款已同意、不在结果页时显示，位置在票区下面。

**选了活动（草稿）**：标签「报名计划」（修改中为「修改中」，条款没同意为「已暂停」）；标题一律「已选 N 场」；
副行一句汇总「X 场立即报名，Y 场预报名等开放」，为 0 的一半不写；地点、时间和场名都在票里，不再复读。
票按开放批次分组，批次头写「现在」（说明「立即报名 N 场」）或 HH:MM:SS（跨天加「明天 / 后天 / N 天后」，说明「预报名，同时提交 N 场」，单场「预报名 1 场」）。
尝试设置一行概括「尝试 <时长>，<最多 N 次 / 不限次数>」，按钮「修改」（展开后「收起」），只在草稿显示。

**检查条**（`✓` / `!` 小标记）：
- 程序组件缺失：只列一条「程序组件缺失」；条款没同意：只列一条「还没有同意使用条款」/「还没有同意新版条款」/「条款状态没能确认」。
- 其余只列没满足的：「登录状态待确认」（登录 unknown 或 checking）/「登录已失效」/「正在登录」/「还没有登录」，以及「北京时间待校准」。演示模式不查这两项。

## 7. 策略、运行与时间线

- 控件名：「尝试时长」（2 分钟 / 10 分钟 / 30 分钟 / 1 小时 / 自动延长（最多 25 分钟） / 直到报名截止）、
  「最多提交次数（0 = 不限）」。概括行里自动延长只写「自动延长」，其余档写选项标签。
- 进度：任务卡写「已提交 N 次（不限次数）」/ 设了上限「已提交 N 次（上限 M 次）」——上限是用户策略，不是学校名额；
  只有真正发起的提交才计数。
- 运行阶段：等待开放（worker 提前开页只是准备，不算提交）→「已开放，准备提交」→
  「正在提交 N 场」，点阵屏标注「本次尝试到 HH:MM:SS」→ 逐场结果。
- 批次表述：已开放批次写「现在 · 立即报名 N 场」；预报名写「HH:MM:SS · 预报名，同时提交 N 场」（跨天加「明天 / 后天 / N 天后」）
  （单场写「预报名 1 场」）。点阵屏等待开放标注「开放时间」，值未公布写「待公布」、
  未校准写「待校准」。两者不可互换：未公布是学校事实，未校准是本机能力。
- 停止条件人话：达到提交次数上限 / 已达到尝试时长上限 / 报名已截止；
  「本次尝试到」始终与学校「报名截止」分开。
- 时间线节点：未发生写「待启动 / 待打开 / 待发生」，不用估算时间冒充事件；
  参考时间用「原定开放」「本次启动」「本次尝试到」；历史时间显示完整日期。
- 签到/签退按「要求 + 时间段」说：需要且有时间 →「签到 19:00–19:40」「签退 21:00–21:20」；
  明确无需 →「无需签到」「无需签退」；详情还没回来 →「签到信息同步中」「签退信息同步中」；
  详情已回来但确实没有数据 →「签到时间待确认」「签退时间待确认」。三态独立，未知不并入「无需」。
- 报名成功回写：已确认成功但学校列表还没同步 →「报名已确认，学校列表正在同步」；
  不说「列表没更新说明没报上」，也不因此把该场重新画成可报名。
- 立即模式只说「立即报名」，只有预报名才说「等待报名开放」；已开放的场次不得出现
  「提前 N 秒打开页面」。（实现侧任务卡仍带含抢单字样的旧复合标签，属待收敛差异，见 §15。）

### 7.1 计划栏：运行中（按实现写，逐字取自 `plan-panel.js` / `task-display.js` / `login.js`）

| 等开放，单场 | 同上 | 这一场等开放，到点自动开始。 |
| 还没有任务 | 准备中 | 标题「正在准备报名」，说明「计划已经接管，正在核对每一场的开放时间。」 |
| 任务都结束、结果还没汇总 | 汇总中 | 标题「正在汇总结果」，说明「每一场都结束了，正在汇总这一轮的结果。」 |

**运行 LED**：提交中整块红色，小字「本次尝试到 <HH:MM:SS>」，截止未知写「待定」；已开放没提交「已开放，准备报名 N 场 准备中」；
等开放「开放时间 <HH:MM:SS>」（最后 10 秒转红），没公布「待公布」，没校准「待校准」；准备中 / 汇总中「计划状态 准备中 / 汇总中」。时刻跨天时前面加「明天 / 后天 / N 天后」。

**运行提醒**（`#run-warn`，登录失效时才出现）：
- 电脑在自动登录：「登录失效了，电脑正在自动登录。计划照常等开放，不用你管。」；正在提交时「登录失效了，电脑正在自动登录（最多约 20 秒），成功后接着提交。」
- 来不及（有场次在提交，或最早一场离开放不到 100 秒）：「登录失效了。<正在提交 / 离开放不到 100 秒>，来不及重新登录，<正在提交的场次 / 这一批>会以“登录失效”结束。」，后面还有场次时加「后面的场次等它结束后重新登录就行。」
- 来得及：「登录失效了，计划还在等。只要在 <时刻> 前重新登录，计划照常继续；否则 <时刻> 开放的那批会以“登录失效”结束。」+ 按钮「重新登录」。前一个时刻是最早一场开放减 100 秒。

**底部**：说明「可以最小化窗口，但不要关闭工具或让电脑睡眠。」（从手机开始的计划追加「这个计划是从手机开始的，在电脑和手机上都能看进度、停止。」）；
按钮「修改计划」「停止计划」（停止中「正在停止…」）。

**修改计划说明**：有场次在提交「有场次正在提交，现在不能修改。」/ 有场次 100 秒内开放「有场次 100 秒内开放，工具已在准备，现在不能修改。」/
其余「还没提交的场次可以放回草稿，改完要重新开始。」；没有还没提交的场次时按钮同样禁用。

**任务卡**（运行中和结果页）：名称 + 标签同排，说明在下，按钮另起一行。

| 状态 | 标签 | 说明 |
|---|---|---|
| 排队 / 等开放，开放时间没公布 | 等待开放 | 提前准备，开放时间待公布 |
| 等开放，还没准备好 | 等待开放 | 提前准备，等到 <时刻> 开放 |
| 等开放，页面已准备好 | 等待开放 | 已准备好，<时刻> 开放时提交 |
| 已开放，还没真正提交 | 准备报名 | 已开放，正在准备提交 |
| 提交中 | 提交中 | 已提交 N 次（上限 M 次 / 不限次数）。最近：<原因>，重试到 <时刻>；截止未知写「等待提交结果」；不写阶段名 |
| 等电脑自动登录 | 同阶段标签 | 电脑正在自动登录，换上新登录态后接着提交 |

运行中的任务说明前带模式前缀（「预报名 · 」/「立即报名 · 」）。「已准备好」要求记下的准备时刻已到，按提交方式取（直接提交看监测开始，页面点击看活动页打开）。
排队和等待中的卡片有按钮「取消这一场」。提交方式另起一行小字：「直接提交，不经过活动页」/「改用页面点击[：<原因>]。活动页已提前打开」。

**登录胶囊（计划运行中）**：学校没明确说失效时保持「已登录」（说明「登录状态保持不变；计划进度见报名区域」，停止中「正在停止计划；已报名的场次不受影响」）；
学校明确返回失效（`expired`）时改走「登录已失效」，电脑在自动登录时走「自动登录中…」，这样计划栏运行提醒和顶部「登录已失效」横幅才出得来；
网络原因的「登录待确认」运行中仍保持「已登录」。

### 7.2 运行记录句（主窗口新增）

同一句紧挨着重复时不再写一行；隔了别的记录再发生，则再写一行。

- 修改计划：「计划已暂停：N 场放回草稿修改」（N 为放回草稿的场数）。
- 手机开始：「从手机开始了报名计划」；有场次时后面接「：」加报名方式计数（「2 场立即报名，1 场预报名等开放」，为 0 的一半不写），拿不到场次只写前半句。
- 列表没加载：「活动列表没加载：<原因>」（原因取失败的原话）。
- 又打开了一次：「又打开了一次，已切回这个窗口」。
- 旧数据迁移成功：「已把 N 个旧数据文件搬到新的数据目录」（N 取后端 `bootstrap.migration.moved` 的真实值）。
- 旧数据迁移失败：「[!] 旧版本的登录信息没能搬过来，其他数据已搬好」；全部失败「[!] 旧版本的数据没能搬过来，旧文件还在原来的位置」；只有设置或运行记录失败「[!] 旧版本的设置或运行记录没能搬过来，登录信息已搬好」。
- 条款状态未知：「[!] 没读到条款同意记录，学校相关操作已暂停」（同一轮未知只写一条）。

## 8. 两层「未确认」分开：计划启动对账 vs 学校报名结果

| 真实情况 | 呈现 | 禁止 |
|---|---|---|
| start_plan 回执丢失，不知计划是否已接纳 | 「正在确认是否启动…」；按钮「正在确认是否启动…」 | 重复点开始；把对账说成报名 |
| 对账 5 秒无结论 | 「结果未确认」+「5 秒内没有确认计划是否启动」；动作「检查计划状态」只读查询 | 重发 start_plan；写「报名失败」 |
| signUp 已发出，结果没有确定回应 | 任务卡「待核对」+「已提交 N 次，没有拿到确定回应」；去学校活动页核对 | 「没抢到」「报名失败」；画失败叉或亮红灯 |
| 学校明确失败（名额满/截止/次数到） | 「报名未成功」+ 停止条件 | 把待核对混进这个数字 |
| 网络/接口无法验证登录态 | 「未提交」+「本场没有提交」 | 「登录失效」「请重新登录」 |
| 计划汇总 | 大数字五项分列、只显示不为 0 的：已报名 / 名额已满 / 报名未成功 / 待核对 / 已取消（没提交的场次并入「报名未成功」，卡片上仍写「未提交」） | 只给一个混合总数 |

**红线**：结果未确认 ≠ 失败；「待核对」的下一步固定是「打开学校活动页核对」；
未知场次不自动重发、不自动开始新计划；整屏视觉与文字同一分类
（含未知=中性琥珀，仅确认失败=失败红）。

## 9. 结果与停止

- 任务卡标签：排队 / 等待开放 / 准备报名 / 提交中 / 报名成功 / 已报名 / 报名未成功 / 错过了 / 名额已满 / 待核对 / 未提交 / 已取消；
  「已提交 N 次」保留；每场结果单独显示。说明逐字见 §7.1、§9.1。
- 计划结论（结果页的标签 / 标题 / 副行）：报名计划完成 / 报名计划部分完成 / 计划已结束，有 N 场需确认 /
  电脑睡眠，错过了开放 / 这次没报上：名额满了 / 报名计划没有成功 / 报名计划已停止，逐字见 §9.1。计划运行中不拿单场结论写计划结论。
- 停止确认遮罩（计划栏内，不是原生对话框）：标题「停止报名计划？」；正文「工具会停止后续尝试。已经发出的提交仍可能成功，
  停止不会取消已成功的报名。」；按钮「继续计划」/「停止计划」。焦点与 Esc 规则见 §9.1。
- 停止后：标题「报名计划已停止」，副行「已提交的场次保留原状态，还没提交的场次已取消。」
  大数字另按结果分列（见 §9.1）；标签写「已停止」/「已停止，需确认」；停止是中性词，不写「失败」；停止不抹已报名事实。
- 演示模式开始前说明策略控件可用；演示全程标注「演示模式」，不访问学校。

### 9.1 计划栏：结果页与停止确认（按实现写，逐字取自 `plan-panel.js`）

**进出时机**：计划结束（`plan_done`）进结果页，计划栏变成独立分支，直到下面任一情形才离开：点「完成，回到活动列表」（回到空草稿，
中窄档回时刻表）；点「重新选择未成功的场次」；开始新计划；用户自己在时刻表改了勾选；进入修改。成功场次被自动移出选择集合**不**会关结果页。
结果页不显示票区、尝试设置、检查条、开始前提醒、还差一步、选择提醒与冲突框、「清空」；只有计划结束且有任务时才有结果页。

**大数字**（最多六格，只显示不为 0 的，自左至右顺序固定）：已报名 / 名额已满 / 报名未成功 / 错过了 / 待核对 / 已取消。
- 已报名含报名成功、已报名，以及「刷新核对」后学校列表已显示报名的场次。
- 报名未成功含学校明确失败的场次，以及没提交的场次（登录状态无法确认）；名额已满、待核对分开数。
- 错过了：电脑睡眠盖住了开放时刻、一次都没提交过的场次（判据与时刻表行级「错过了」相同），单列，不计入报名未成功。
- 不数还在排队 / 等待 / 提交中的场次。

**标题与副行**，按顺序判断：

| 情形 | 标签 | 标题 | 副行 | 外框 / 小 LED |
|---|---|---|---|---|
| 用户停止 | 已停止（有待核对时「已停止，需确认」） | 报名计划已停止 | 已提交的场次保留原状态，还没提交的场次已取消。 | 有待核对时警示框，否则中性 |
| 每场都已报上（且每场都已有终态） | 报名成功 | 报名计划完成 | 每场结束时都向学校核对过。 | 绿框，小 LED ✓ |
| 有报上的，也有别的 | 部分完成 | 报名计划部分完成 | 有待核对：有 N 场需要到活动页核对，结果以学校为准。／否则有名额已满：有 N 场名额已满，不是工具出错。／其余：结果以学校活动页为准。 | 警示框 |
| 没报上的，有待核对 | 需确认 | 计划已结束，有 N 场需确认 | 工具不会自动重发，到学校活动页核对。 | 警示框 |
| 电脑睡眠盖住了开放时刻，且没有提交过 | 错过了 | 电脑睡眠，错过了开放 | 运行计划时别让电脑睡眠：在 Windows 电源设置里把睡眠改成“从不”，并保持插电。 | 红框，不画小 LED |
| 只有名额已满 | 名额已满 | 这次没报上：名额满了 | 学校的名额在开放后被报满了，不是工具出错。 | 警示框 |
| 其余 | 未成功 | 报名计划没有成功 | 每场的原因都列在下面。 | 红框，小 LED ✕ |

只有全部报上和全部没成功才显示小 LED（缩小、没有下方小字），其余结果页不显示 LED。「错过了」只在没有报名未成功的场次时作结论，有报名未成功时落到「其余」；全部报上与只有名额已满的判断都要求没有错过了的场次。

**页脚**：「重新选择未成功的场次」（有能重选的场次时才显示）、「完成，回到活动列表」。可重选的是报名未成功、错过了和已取消的场次，
不含名额已满和待核对（工具不自动重发），并且要还能加入计划（没截止、没报上、不和已报名冲突）。

**结果页任务卡标签与说明**：
- 待核对：标签「待核对」，说明「已提交 N 次，没拿到确定回应；结束时向学校核对也没查到结果。去活动页看一眼，或稍后刷新核对。工具不会再自动重发。」，只有按钮「刷新核对」。
- 点过「刷新核对」后学校列表已显示报名：标签「报名成功」，说明「刷新核对：学校显示已报名」；还没显示：「刷新核对：学校列表还没显示已报名，可能有延迟，去活动页看一眼；本工具不会再自动重发」。
- 名额已满：标签「名额已满」，说明「学校说报名人数已满，这一场到此结束，不再提交。不是工具出错。」，已提交过再加「已提交 N 次」。
- 已取消：计划被停止时「计划已停止，这一场没有提交」，逐场取消时「你取消了这一场」。
- 报名成功：说明「学校回“<原话>”，结束时向学校核对过：已报名」，没有原话则「结束时向学校核对过：已报名」；标签「已报名」表示之前就报过。
- 错过了：标签「错过了」，说明「电脑睡眠期间到了开放时间，没有提交。」
- 没提交（登录状态无法确认）：标签「未提交」，说明「登录状态无法确认，本场没有提交 · 检查网络后刷新重试」。
- 其余失败：「提交了 N 次（<结束结论>）」，结论用后端的结束标签，没有则用停止原因的同义词（如「报名已截止」「达到最大提交次数」）。

**停止确认遮罩**（计划栏内，不是原生对话框；只盖计划栏）：标题「停止报名计划？」；正文「工具会停止后续尝试。已经发出的提交仍可能成功，停止不会取消已成功的报名。」；
按钮「继续计划」「停止计划」。
- 点计划栏「停止计划」打开，焦点落「继续计划」。
- Esc 和「继续计划」只关遮罩、不停止，并把焦点还给计划栏的「停止计划」按钮（按钮不可用则不还）。
- Tab / Shift+Tab 只在两个按钮之间循环；Enter 交给当前按钮；Ctrl+F 和 / 不抢焦点；Esc 不会穿透去清空选择。
- 点遮罩里的「停止计划」：关遮罩（不还焦点），随即按钮变成「正在停止…」；若此时计划恰好已结束或已在停止，只关遮罩，不再发停止请求。
- 遮罩开着时计划结束，遮罩自动收起；焦点原本在遮罩里就移到「完成，回到活动列表」（不可见则落到计划栏本身）。

### 9.2 托盘通知（计划结束）

标题三态（`plan_service.py` 的 `plan_done_notice`，照原型 toastTitle）：

|---|---|
| 全部成功（没有待核对、名额已满、没成功的场次） | 报名计划完成 |

## 10. 独立北京时间入口（决策 012，单一入口五态）

顶栏唯一时间入口（`#clock`）：正常只显示「北京时间 + HH:MM:SS + 状态图形」；
未校准显示「待校准」；演示显示「演示时间」。主界面不出现 NTP、毫秒、
「与电脑日期差 N 天」或「点此重新校时」长句——这些都在详情浮层。

| 界面状态 | 顶栏 | 详情浮层状态行 + 说明 |
|---|---|---|
| ready | 北京时间 + 时分秒 | 「已校准」·「报名时间和倒计时均以北京时间为准。」 |
| syncing | 校准中… | 「正在校准…」·「正在获取网络时间。报名计划需在校准完成后启动。」 |
| holdover | 北京时间 + 时分秒 | 「使用上次校准结果」·「时间仍可用，工具会自动重试校准。」 |
| unavailable | 待校准 | 「时间校准失败」·「报名计划暂不可启动。检查网络后重试。」 |
| demo | 演示时间 | 「演示时间」·「使用示例活动和时间，不会提交报名。」 |

详情浮层内容：时间与日期、状态、最近校准（刚刚 / N 分钟前 / 尚未完成）、
估计误差（约 ±N 秒，非零不显示 ±0.00）、使用记录（上次退出至本次启动、登录预计剩余时间）、
时间来源（校准来源、学校 HTTP 时间粗测仅诊断）、按钮「重新校准时间」（失败态「重试校准」）、
反馈行（只在这里，不占结果框）。固定说明：「不会修改电脑时间」；
「登录剩余时间仅供参考，以学校校验为准。」

- 「最近校准」由权威 `age_s` 加接入后的经过时长推导：F5 / 页面重载接入旧锚点
  显示真实年龄（如「10 分钟前」），不得刷新成「刚刚」。
- 估计误差是**采样时误差 + 采样后漂移**；采样前的漂移已包含在权威快照里，
  不重复相加，也不因为时钟详情打开而改变可用性判断。
- 无可信当前时间但开放时间已知时：列表保留绝对时刻并标「待校准」；
  大屏只写「时间待校准」+ 一个恢复入口（打开本详情）；
  可报名/下一场等依赖时钟的计数写「待确认」，不显示伪 0 或伪 6；
  已报名等学校静态事实照常保留。恢复校准后原地重算分组、计数与倒计时，

  - 「报名计划会停止，还没提交的 N 场不会再报名。手机也会断开。」（运行中；N 缺字段写「还没提交的场次」，手机没开时不写末句）／「登录状态会保留，下次打开不用重新登录。」（空闲）。
- 隐藏禁用：「现在叫不回来：托盘图标没建起来，手机也没连着，所以不能隐藏。」
- 脚部：勾选「以后都这样，不再询问」居左；「先不关」。
- 确认步正文：「还没提交的 N 场不会再报名。已经成功的报名不受影响。」（N 缺字段写「还没提交的场次」）；脚部「返回」｜「停止计划并退出」（红色实心）。
- Esc：选择步等同「先不关」（不发动作）；确认步回选择步，不触发全局清空已选。
- 隐藏成功：托盘气泡一次，标题「窗口已隐藏，工具在后台运行」，正文「报名计划照常运行。点右下角托盘图标回来，也可以在手机页点“显示电脑窗口”。」；原型的模拟桌面与静态时钟是演示包装，不做。

## 13. 红线汇总

1. 未知（登录 / 报名 / 计划）不写成失败，不诱导重登，不自动重发。
2. 「选中」不等于「开始」；「停止」不等于「取消学校报名」；「本次尝试到」≠「报名截止」。
3. 估算写「约」；没有锚点就不报数；不承诺成功、时效或零误差。
4. 时钟一切展示与执行只认独立北京时间；未校准显示「待校准」；不引导改系统时间。
   只有学校没给开放时间才写「待公布」；本机没有可信当前时间写「待校准/待确认」，
   不推断可报名数量，不伪造 0/6。
5. 一个问题一个负责区域；恢复动作按钮与实际调用一致；F5 后终态文案逐字一致。
6. 不全局替换中文字符串：不改正则归因、字段名、机器协议、网络策略与状态机。

- 运行中：「报名计划运行中不能撤回同意，先停止计划。」
- 确认条：「撤回后，登录、自动登录、活动列表和报名计划会停用。已保存的账号密码和登录信息不会删除。要删除账号密码，在“登录恢复”里清除。」按钮「先不撤回」「确认撤回」（红色实心）。

**三件套逐字（2026-11-08 按代码）**

- **全文阅读器**：标题「使用条款与隐私」；副行「版本 <程序要求版本>。本份《用户协议》与《隐私政策》 <副本版本>。」＋状态段「你还没有同意。」或「你之前同意的是 <旧版>，新版还没同意。」（未知态不显示状态段）。页签「用户协议」「隐私政策」「开源许可」；右侧注「标着“本版新增”的是这次的改动」。脚部勾选「我已阅读并同意《用户协议》和《隐私政策》」＋「暂不使用」「同意并继续」（勾选前禁用）；只读态状态行「已同意《用户协议》与《隐私政策》 <版本>（MM-DD HH:mm 同意）；更新后会再次展示并要求重新同意。」，脚部只有「关闭」。Esc 提示「Esc 关闭」，保存中「正在保存…」。

- **条款更新框**：标题「使用条款更新了」；副题「新版 X，你之前同意的是 Y。同意新版后才能继续登录和报名。」；正文「这次主要改了：」＋三条（每条带「新增」徽章）：
  1. 「手机访问会经过的第三方：Cloudflare 临时隧道或你自己的 Tailscale 网络」
  2. 「下载安装包与组件包时会访问 GitHub，下载后先核对 SHA-256」

**规则**：

1. **区分从未同意、更新未同意与未知**：从未同意 → 横幅「还没有同意使用条款。」；同意过旧版 → 「使用条款更新了，还没有同意新版。」；缺版本（未知）→ 「条款状态没能确认。」并 fail closed，三者不混用同一句话。
2. **坏回执不说「没有记录同意」**：回执缺字段/自相矛盾只说「保存结果无法确认（回执缺字段
   或自相矛盾，版本 X）；请点『重新确认状态』核对本机记录」——不承诺撤销已发出的事务，
   也不在前端擅自解锁。
3. **版本不匹配只指向前**：说「本份条款（X）与程序要求的版本（Y）不一致，没有解锁；请重新
   下载完整版本后再确认。」——不把「重新打开同一份副本」说成版本修复（旧句
   「请重新打开条款再确认一次」已废止）。
4. **超时不假称结果**：「保存结果未确认」不得写成失败、取消或已拒绝；「正在保存…」期间
   不提供任何可点击的退出动作。

## 静默自动登录（2026-11-11）

口径：电脑能自己把登录补回来时，恢复成功之前不打扰用户；补不回来、或已经转人工，就把失效提醒还回来并说明原因。

| 场景 | 胶囊 | 空态 / 提示 | 按钮 |
|---|---|---|---|
| 明确失效，电脑能自己登录 | 自动登录中…（沿用既有词） | 空态标题「正在自动登录」，说明「电脑正在用保存的账号自动登录，登录好以后这里会自动加载。」 | 刷新 |
| 明确失效，静默登录失败过一次 | 登录已失效 | 仍按上一节的「登录已失效」文案，后台还会继续重试 | 重新登录 |
| 明确失效，补不回来（没装识别 / 没账号 / 密码被拒 / 条款未同意） | 登录已失效 | 同上，不解释内部原因 | 重新登录 |
| 自动发起的一场转人工 | 登录已失效 | 对话框验证码步上方提示：认满 3 次「自动识别 3 次没认对，请输入验证码。」；识别结果不合规「电脑没认出这张验证码，请输入验证码。」 | 重新登录 |

规则：

1. **不把「正在自动登录」写成「登录已失效」**：静默恢复期间胶囊、横幅、列表空态都不出现失效字样，运行记录也不记登录失败。
2. **失败一次就还回提醒**：静默登录第一次失败后立刻恢复「登录已失效」，不让用户对着「自动登录中…」无限等。
3. **转人工不新开一场**：点「重新登录」接上电脑正在跑的那一场，直接输这张验证码；保存过账号的不再问「自动登录一次？」。
4. **验证码错只说换图**：验证码不对只换图并要求重输，不显示成错误，也不退回账号密码表单；网络与其他错误提示「这次没登录上，可以再试一次」，再试时重新开一场。
