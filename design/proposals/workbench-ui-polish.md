# 工作台界面打磨：时间轴列表、设置抽屉与状态过渡

## 状态

proposed（2026-11-11 与用户讨论定方向，效果稿已看过；原型和代码都还没改）

## 目标

用户和目标用户在实际使用中反映了三类问题：

- 活动列表太挤，看着不舒服。
- 设置抽屉字太多、排版拥挤，状态看不明白。
- 来回操作以后，界面上的状态怎么变的说不清，有时显示还不对。

这份提案管视觉和过渡规则。「显示不对」的那部分是代码缺陷，按「前置：状态残留修复」另行修，不靠改样式解决。

## 非目标

- 不改报名调度、登录机制、学校接口和数据模型。
- 不改「不可加入」「错过了」「报名时间待公布」的判定和分组，只改样子和文案。
- 不改整体配色：浅色时刻表 + 深色计划栏 + 琥珀点阵倒计时保持不变。
- 不碰计划 `plan-20261112-component-upgrade-recovery` 正在改的文件，等它提交后再排。

## 方案概述

效果稿在 claude.ai 的私有设计画布「工作台视觉方案」（用户本人可见）：<https://claude.ai/artifact/PShEY3o2u2cpyqbsAKhgim>。画布用的是网页字体，断行以并入原型后的 Edge 截图为准。

### 1. 活动列表改成时间轴

- 左边一条竖线，每个开放时刻一个节点，节点旁写时刻和倒计时，只写一次；同一时刻开放的几场挂在同一节点上。
- 「现在 HH:MM」画在竖线上。节点样式：已开放实心橙、下一批琥珀带光晕、以后的空心灰、待公布虚线。
- 分组顺序照现有 `groupTimetable`：正在开放 → 现在线 → 按天 → 报名时间待公布 → 已报名 → 已截止。已报名、已截止放在时间轴下方，不占节点。
- 每张卡片固定四层：
  1. 名字（最多两行）+ 右上两格奖励（实践分、工资；详情没回来写「同步中」，没公布写「未公布」）。
  2. 怎么报：圆点 + 预报名 / 立即报名，后面跟「报后可退 / 报后不可退」，开放中再写报名截止。
  3. 四个固定格：举办、地点、签到、签退，始终在同一位置。跨天写全日期和「跨 N 天」，不需要的写「无需签到」。
  4. 只在需要时出现的一条：琥珀 = 与已选的时间重叠（文案同现有）；淡红 = 错过了的原因；灰 + 锁 = 报名时间待公布。
- 「不可加入」照现有做法：复选框置灰，右上虚线「不可加入 ⓘ」，卡片上不写原因；鼠标停约 140ms 或键盘聚焦才弹原因气泡。
- 「错过了」判定不变（`missedBySleep`），在卡片里写明原因：「电脑在 HH:MM 开放时睡着了，没有提交 · 还能报」，已截止的结尾写「· 已截止」。
- 已报名能取消的，照现有直接给「可取消至」和「取消报名」。

### 2. 设置抽屉用「一项一行」

- 每个功能一行：图标、名称、一句状态、一个主按钮；说明压成一句，路径、通道选择、版本等收进展开区。
- 「登录」组放一张清单「失效后自动登录 · 还差 N 步」，每一步旁边直接给按钮（填写账号密码 / 安装验证码识别）。
- 「程序」组合成一张卡：关闭窗口时、版本与检查更新、本机数据、条款与隐私各一行。

### 3. 组件状态的过渡

同一行、同一位置，只换三样：圆点颜色、状态字、右侧按钮；进度条长在这一行里，不整块换内容。颜色含义固定：

| 颜色 | 含义 |
|---|---|
| 灰 | 没装、没开 |
| 蓝 | 正在做（下载、校验、检查中） |
| 绿 | 能用 |
| 琥珀 | 要留意或要你处理 |
| 红 | 坏了 |

### 4. 顶栏状态的过渡规则

通用规则：

- 动作 200ms 内做完就不显示任何转圈。
- 手里已有数据时不清空、不出骨架，在后台更新；骨架只用于第一次加载。
- 成功的打勾、高亮 1.5 秒左右自己褪掉，不弹窗。
- 状态切换 180ms 淡入。

各元素：

| 元素 | 状态与显示 |
|---|---|
| 北京时间 | 已校准绿点；校准中蓝点慢闪；沿用上次琥珀点 +「沿用 N 分钟前」；没校准 `--:--:--` + 横幅说明影响什么 |
| 登录胶囊 | 第一次检查「检查登录…」；已登录绿色 + 上次校验时刻；已登录后再检查保持绿色加小转圈（见第 6 节）；自动登录中蓝色转圈，不先闪红；待确认琥珀；已失效红色，横幅直接给登录或输验证码的按钮 |
| 手机 | 没开不显示；开启中转圈；等手机连接琥珀慢闪；已连接绿；断开灰色「已断开 · N 分钟前」，不算错误 |
| 刷新按钮 | 平时「刷新」；进行中图标转圈并禁用；成功打勾约 1.5 秒；失败马上恢复可点，原因写在列表上方；后台自动刷新时按钮不动 |

### 5. 活动列表的六种加载、刷新样子

1. 第一次加载：骨架 3 行，形状和真实行一致。
2. 已有列表时刷新：内容留着、略淡，顶上一根细进度条。
3. 刷新失败、有旧列表：列表和勾选不动，上方淡琥珀一条「没连上学校，下面还是 HH:MM 的列表」+ 重试。
4. 失败、也没有旧列表：整块空态，一个原因、一个按钮。
5. 学校回了 0 场：空态写明「这不是登录问题」。
6. 筛选后没有：只有这种给「清除筛选」。

### 6. 本轮已定的三项（用户 2026-11-11 同意）

1. **手动刷新失败时保留旧列表和勾选**，按第 5 节第 3 种显示。从没加载成功过的仍按第 4 种。理由：清空不带来任何好处，还丢掉用户的勾选；开始报名时后台会再核对一遍。需要修改 `docs/UI_SPEC.md` §5.20「手动刷新失败的老行为不变」。
2. **已登录后再检查，胶囊保持绿色「已登录」，加小转圈和「正在确认」**；学校明确说失效才变红。只改显示：能不能开始报名仍按 `local/ui/views/plan-panel.js` 里「不在检查中且学校确认有效」的条件判断，不放宽。需要修改 `docs/UI_SPEC.md` 的登录胶囊规则。
3. **卡片四个固定格一直显示**。中、窄档改成两行文字：「举办 … · 地点 …」「签到 … · 签退 …」。

## 前置：状态残留修复

讨论中按「每个临时状态在哪设、在哪清、每条退出路径是否都清」排查，找到 10 处会让界面显示不对的缺陷，加上「错过了」的文案修改，共 11 项，已整理成任务卡交给指挥会话派发。它们不依赖本提案，可以先修：

- 「放弃修改，按原计划继续」不恢复原来的勾选。
- 停止没成功或计划先自然结束时，界面卡在「修改中」。
- 程序自己发起的刷新失败会清空列表和勾选。
- 每次把窗口从最小化恢复，列表都闪一次。
- 胶囊可能停在「自动登录中…」。
- 关掉「重新登录」对话框会取消电脑正在进行的自动登录。
- 学校判登录失效时，手机页可能仍写「电脑上的登录有效」。
- 手机「核对计划」弹层不随轮询更新，点开始可能没反应。
- 手机「最近同步」用的是手机本机时钟。
- 安装程序启动后「检查更新」一直不可点（记为已知限制，不改代码）。
- 「错过了」把原因写进行里。

2. 设置抽屉展开后的细节、填写账号密码的表单、各组件出错时的样子还没画。
3. 自动登录失败时用什么渠道告知用户，见提案 [auto-relogin-failure-notice.md](auto-relogin-failure-notice.md)。
4. 时间轴卡片比现在的行高（约 120px 对 48px），一屏场次变少，要用户实际用过才知道能不能接受。
