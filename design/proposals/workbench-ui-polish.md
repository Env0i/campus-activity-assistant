# 工作台界面打磨：时间轴列表、设置抽屉与状态过渡

## 状态

proposed（2026-11-11 与用户讨论定方向，效果稿已看过；原型和代码都还没改）

## 目标

用户和目标用户在实际使用中反映了三类问题：

- 活动列表太挤，看着不舒服。
- 设置抽屉字太多、排版拥挤，状态看不明白。
- 来回操作以后，界面上的状态怎么变的说不清，有时显示还不对。

这份提案管视觉和过渡规则。「显示不对」的那部分是代码缺陷，按「前置：状态残留修复」另行修，不靠改样式解决。

## 非目标

- 不改报名调度、登录机制、学校接口和数据模型。
- 不改「不可加入」「错过了」「报名时间待公布」的判定和分组，只改样子和文案。
- 不改整体配色：浅色时刻表 + 深色计划栏 + 琥珀点阵倒计时保持不变。
- 不碰计划 `plan-20261112-component-upgrade-recovery` 正在改的文件，等它提交后再排。

## 方案概述

效果稿在 claude.ai 的私有设计画布「工作台视觉方案」（用户本人可见）：<https://claude.ai/artifact/PShEY3o2u2cpyqbsAKhgim>。画布用的是网页字体，断行以并入原型后的 Edge 截图为准。

### 1. 活动列表改成时间轴

- 左边一条竖线，每个开放时刻一个节点，节点旁写时刻和倒计时，只写一次；同一时刻开放的几场挂在同一节点上。
- 「现在 HH:MM」画在竖线上。节点样式：已开放实心橙、下一批琥珀带光晕、以后的空心灰、待公布虚线。
- 分组顺序照现有 `groupTimetable`：正在开放 → 现在线 → 按天 → 报名时间待公布 → 已报名 → 已截止。已报名、已截止放在时间轴下方，不占节点。
- 每张卡片固定四层：
  1. 名字（最多两行）+ 右上两格奖励（实践分、工资；详情没回来写「同步中」，没公布写「未公布」）。
  2. 怎么报：圆点 + 预报名 / 立即报名，后面跟「报后可退 / 报后不可退」，开放中再写报名截止。
  3. 四个固定格：举办、地点、签到、签退，始终在同一位置。跨天写全日期和「跨 N 天」，不需要的写「无需签到」。
  4. 只在需要时出现的一条：琥珀 = 与已选的时间重叠（文案同现有）；淡红 = 错过了的原因；灰 + 锁 = 报名时间待公布。
- 「不可加入」照现有做法：复选框置灰，右上虚线「不可加入 ⓘ」，卡片上不写原因；鼠标停约 140ms 或键盘聚焦才弹原因气泡。
- 「错过了」判定不变（`missedBySleep`），在卡片里写明原因：「电脑在 HH:MM 开放时睡着了，没有提交 · 还能报」，已截止的结尾写「· 已截止」。
- 已报名能取消的，照现有直接给「可取消至」和「取消报名」。

### 2. 设置抽屉用「一项一行」

- 每个功能一行：图标、名称、一句状态、一个主按钮；说明压成一句，路径、通道选择、版本等收进展开区。
- 「登录」组放一张清单「失效后自动登录 · 还差 N 步」，每一步旁边直接给按钮（填写账号密码 / 安装验证码识别）。
- 「程序」组合成一张卡：关闭窗口时、版本与检查更新、本机数据、条款与隐私各一行。

### 3. 组件状态的过渡

同一行、同一位置，只换三样：圆点颜色、状态字、右侧按钮；进度条长在这一行里，不整块换内容。颜色含义固定：

| 颜色 | 含义 |
|---|---|
| 灰 | 没装、没开 |
| 蓝 | 正在做（下载、校验、检查中） |
| 绿 | 能用 |
| 琥珀 | 要留意或要你处理 |
| 红 | 坏了 |

### 4. 顶栏状态的过渡规则

通用规则：

- 动作 200ms 内做完就不显示任何转圈。
- 手里已有数据时不清空、不出骨架，在后台更新；骨架只用于第一次加载。
- 成功的打勾、高亮 1.5 秒左右自己褪掉，不弹窗。
- 状态切换 180ms 淡入。

各元素：

| 元素 | 状态与显示 |
|---|---|
| 北京时间 | 已校准绿点；校准中蓝点慢闪；沿用上次琥珀点 +「沿用 N 分钟前」；没校准 `--:--:--` + 横幅说明影响什么 |
| 登录胶囊 | 第一次检查「检查登录…」；已登录绿色 + 上次校验时刻；已登录后再检查保持绿色加小转圈（见第 6 节）；自动登录中蓝色转圈，不先闪红；待确认琥珀；已失效红色，横幅直接给登录或输验证码的按钮 |
| 手机 | 没开不显示；开启中转圈；等手机连接琥珀慢闪；已连接绿；断开灰色「已断开 · N 分钟前」，不算错误 |
| 刷新按钮 | 平时「刷新」；进行中图标转圈并禁用；成功打勾约 1.5 秒；失败马上恢复可点，原因写在列表上方；后台自动刷新时按钮不动 |

### 5. 活动列表的六种加载、刷新样子

1. 第一次加载：骨架 3 行，形状和真实行一致。
2. 已有列表时刷新：内容留着、略淡，顶上一根细进度条。
3. 刷新失败、有旧列表：列表和勾选不动，上方淡琥珀一条「没连上学校，下面还是 HH:MM 的列表」+ 重试。
4. 失败、也没有旧列表：整块空态，一个原因、一个按钮。
5. 学校回了 0 场：空态写明「这不是登录问题」。
6. 筛选后没有：只有这种给「清除筛选」。

### 6. 本轮已定的三项（用户 2026-11-11 同意）

1. **手动刷新失败时保留旧列表和勾选**，按第 5 节第 3 种显示。从没加载成功过的仍按第 4 种。理由：清空不带来任何好处，还丢掉用户的勾选；开始报名时后台会再核对一遍。需要修改 `docs/UI_SPEC.md` §5.20「手动刷新失败的老行为不变」。
2. **已登录后再检查，胶囊保持绿色「已登录」，加小转圈和「正在确认」**；学校明确说失效才变红。只改显示：能不能开始报名仍按 `local/ui/views/plan-panel.js` 里「不在检查中且学校确认有效」的条件判断，不放宽。需要修改 `docs/UI_SPEC.md` 的登录胶囊规则。
3. **卡片四个固定格一直显示**。中、窄档改成两行文字：「举办 … · 地点 …」「签到 … · 签退 …」。

### 7. 2026-11-12 追加的决定（用户与指挥会话）

1. **组件「坏了」的按钮改为「重新安装」**，走和「没装」同一条在线下载路径；「导入组件包」收进展开区，不再是主按钮。
2. **组件「检查中」超过 30 秒给「重试」并写明原因**。需要后端在组件锁等待超时后告诉界面原因，下一版一起做。
3. **琥珀色的例外**：点阵倒计时的琥珀只表示时间，不表示警告，写进规格；其余「要你留意」照用琥珀。
4. 画板与最终效果由指挥会话和用户一起定稿、实现；本提案的视觉与过渡改动全部放到 1.2.2 之后的版本。

### 8. 画板待补（2026-11-14 已补齐，见第 10 节）

- 组件：补「需要更新」（琥珀，按钮「更新组件」）与「下载失败」（红条写原因，按钮「重新下载」）；手机访问补「装好未开启」「等手机连接」「已停用」。
- 计划栏：等开放、修改中、提交中、结果之间的过渡，以及停止没成功、计划先自然结束、放弃修改这几条退出路径。
- 更新：检查更新 → 下载 → 校验 → 等重启 → 切换版本。
- 重新登录对话框：电脑自动识别 → 转成要你输验证码，以及自动登录中关掉对话框不取消这一场。
- 手机页的对应状态。

### 9. 横幅与行内提示能不能关（用户 2026-11-12 定方向）

**顶部横幅**（主窗口最上方，一次只显示一条）不全部能关：

- 一次性通知（电脑刚睡眠、工具已经开着、数据搬迁结果）：「知道了」关掉，本次运行不再出现。手机页的「配对成功」同样能关。
- 持续状态（网络断开、登录无法确认、登录已失效、北京时间没校准、登录信息没搬过来）：给「收起」，不是彻底关。收起后顶栏对应的胶囊或圆点照样亮着；状态变过一次再回到原状态、点了被它挡住的动作（如开始报名）、或报名计划在跑而这个状态会让报名失败时，横幅重新出现。收起只记这一条、这一次状态，排在后面的横幅照常接上。
- 不给收起：条款没同意（整个工具停着，横幅是唯一出路）、组件或运行环境出错（工具基本不能用）。

**行内提示**（设置抽屉里某一项自己的说明、失败原因、成功提示）可以关：

- 说明文字、失败红条、「已导入并启用」这类提示带关闭按钮；关掉只收这一条，下一次新的失败或成功会重新出现。
- 状态标签（如「需要更新」）、主按钮、进度条不能关，它们表示这一项现在的状态。

### 10. 状态机画板与 13 项决定（用户 2026-11-13、14 定）

第 8 节列的缺口已在同一块设计画布上补齐，共 12 块，每块是「状态图 + 转移表」：

| 画板 | 内容 |
|---|---|
| ① 组件 | 验证码识别、手机控制共用一台状态机：安装路径与读状态 |
| ② 手机访问 | 叠在「手机控制已启用」之上：开启、等手机连接、已连接、已断开、停止 |
| ③ 登录结论 | 顶栏胶囊的十个状态 |
| ④ 重新登录对话框 | 各步骤，以及「关对话框」按谁发起分两种 |
| ⑤ 报名计划栏 | 草稿、开始请求、等开放、提交中、停止、修改中、结果 |
| ⑥ 版本更新 | 检查、下载、校验、启动安装程序 |
| ⑦ 列表刷新与取消报名 | 用户刷新与程序刷新分开；每一行自己的取消报名 |
| ⑧ 手机页 | 配对与同步；电脑上的状态在手机页写什么 |
| ⑨ 每一场报名 | 等待开放、准备报名、提交中和八种结束 |
| ⑩ 自动登录的前提 | 设置里「还差 N 步」清单的六种样子；前提与登录失效后去向的对照 |
| ⑪ 顶部横幅 | 九级优先顺序；一次性、能收起、不能动三类 |
| ⑫ 状态机之间的联动 | 计划在跑时登录失效；窗口隐藏再回来；关窗口 |

画板上的箭头分三种：代码已有的、1.2.2 与 1.2.3 刚修的、这一版要加的。转移表在实现时原样写进 `docs/UI_SPEC.md`，样子并进原型；在那之前以画布为准。

画板上要定的 13 件事，用户都按指挥会话的建议定了：

1. 电脑认不出验证码、要用户输时，登录胶囊用琥珀色，写「要你输验证码」，不用红色。
2. 自动登录这一次没成、稍后会再试时，这一版就显示，胶囊写「登录已失效 · N 分钟后再试」。
3. 组件「检查中」：之前有状态就保留原来的字，只把圆点变蓝；之前没有状态才写「正在确认组件状态…」。
4. 取消下载后直接回到「没装」，不留「已取消」。
5. 安装失败后回到安装前的状态（之前已启用的旧版本照用），带一条红色说明。
6. 计划栏的「准备报名」「汇总中」这些小阶段留着，作为「提交中」里的一条子进度。
7. 安装程序启动后加一个次要按钮「安装程序没出现？」，点了回到「可以安装」。原来记为已知限制的那一项由此解除。
8. 手机 2 分钟没来算「已断开」。
9. 手机页六句新的登录说明：确认中沿用「电脑上的登录有效。」；待确认「电脑暂时确认不了登录状态」；稍后重试「电脑上的登录已失效，5 分钟后会再试」；首次检查「电脑正在检查登录」；没登录过「请到电脑上登录」；登录中「电脑上正在登录」。
10. 安装程序没启动起来时，留着已下载并校验过的安装包，写明原因，可以再点「启动安装程序」，不用重新下载。
11. 任务卡的「未提交」标签留着（登录状态确认不了、没发出提交），不并进「报名未成功」。
12. 有保存的账号但电脑认不了验证码时登录失效，胶囊同样显示琥珀「要你输验证码」。
13. 要输验证码、计划还来得及时的两句新文案：横幅「要你输验证码。报名计划还在等，开放前 100 秒以前输完就照常继续。」，按钮「输入验证码」；计划栏「登录失效了，电脑认不出验证码。只要在 HH:MM:SS 前输完验证码，计划照常继续；否则 HH:MM:SS 开放的那批会以“登录失效”结束。」

画板上还有四处标了「待核」，实现前要对着代码补上：任务卡「错过了」的说明行；窗口回来时登录状态从哪里恢复；退出时组件或新版本正在下载怎么办；手机页计划部分的用字。

## 前置：状态残留修复

讨论中按「每个临时状态在哪设、在哪清、每条退出路径是否都清」排查，找到 10 处会让界面显示不对的缺陷，加上「错过了」的文案修改，共 11 项，已整理成任务卡交给指挥会话派发。它们不依赖本提案，可以先修：

- 「放弃修改，按原计划继续」不恢复原来的勾选。
- 停止没成功或计划先自然结束时，界面卡在「修改中」。
- 程序自己发起的刷新失败会清空列表和勾选。
- 每次把窗口从最小化恢复，列表都闪一次。
- 胶囊可能停在「自动登录中…」。
- 关掉「重新登录」对话框会取消电脑正在进行的自动登录。
- 学校判登录失效时，手机页可能仍写「电脑上的登录有效」。
- 手机「核对计划」弹层不随轮询更新，点开始可能没反应。
- 手机「最近同步」用的是手机本机时钟。
- 安装程序启动后「检查更新」一直不可点（记为已知限制，不改代码）。
- 「错过了」把原因写进行里。

## 待确认问题

1. 中档、窄档、矮窗口和手机页的时间轴还没画；窄档下竖线是否保留未定。
2. 设置抽屉展开后的细节、填写账号密码的表单、各组件出错时的样子还没画。
3. 自动登录失败时用什么渠道告知用户，见提案 [auto-relogin-failure-notice.md](auto-relogin-failure-notice.md)。
4. 时间轴卡片比现在的行高（约 120px 对 48px），一屏场次变少，要用户实际用过才知道能不能接受。
