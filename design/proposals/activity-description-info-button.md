# 活动简介问号入口

## 状态

proposed

## 目标

让用户在活动列表中快速查看学校提供的活动简介、地点、活动时间、报名时间和面向范围，减少为了确认活动内容而反复打开学校网站的需要。

第一阶段面向桌面列表。手机页后续复用同一份详情字段和缓存逻辑。

## 非目标

- 不为详情另起请求：列表路径已为展示中的每场活动请求 getInfo（签到、奖励字段），`hdms` 随同一个回包带回，不新增批量详情请求。
- 不改变报名资格、报名模式、冲突检查或计划提交逻辑。
- 不在本提案阶段修改学校接口契约或猜测详情字段语义。
- 不把学校返回的富文本直接插入页面。
- 不把手机页和桌面页同时纳入第一阶段实现。

## 方案概述

### 列表入口

在活动名称旁增加一个小型问号按钮。按钮使用独立的 `button` 元素，带有「查看活动简介」的可访问名称。点击问号时阻止事件继续传播，不能触发行选择或整行点击。

### 详情浮层

点击后打开详情浮层，先给关键事实，再给简介正文（2026-11-24 原型复核时调整）：

1. 标题：活动名称；副标题：活动类型 · 所在分组
2. 关键事实两列：活动时间、地点；报名时间、面向范围各占一整行
3. 简介正文

名称和类型已经在标题区，不再在正文里重复一行。用户点问号多半是想确认「能不能去、什么时候、在哪」，这些放在简介前面，长简介不会把它们挤到下面。

简介正文使用纯文本节点渲染，保留换行，不执行学校返回的 HTML。没有简介时显示「学校未提供活动简介」。详情请求失败时显示「活动简介暂时没同步下来」，不阻止勾选和开始计划。

### 请求与缓存

问号第一次点击时按活动 ID 懒加载详情。当前代码已经有 `GET /rjyHd/getInfo/{activity_id}` 的详情入口和进程内详情缓存，提案复用这条路径，不为列表新增批量详情请求。

详情按活动 ID 保存，只在同一次列表加载内去重；每次刷新都会起新的列表 worker，上一次的详情不会带到下一次，点开时用刷新后的回包。详情请求失败不写入永久的空简介，后续点击允许重试。

### 数据映射

2026-11-24 用户用 40 份真实详情响应核对过字段语义（真实取值不进仓库）：

- `hdms`：活动简介正文，纯文本，样本长度 91～352 字。映射为本地 `description`。
- `hdmxfw`：面向范围的类型代码。样本里只见过 0～3：0 全校，1 限分公司，2 限年级，3 同时限年级和分公司。这是从样本归纳的，不是学校公布的字典。
- `mxfw`：面向范围的显示文字，内容随 `hdmxfw` 变：0 时是「全校」一类文字，1 时是分公司名单，2 时是年级，3 时是「年级：…; 分公司：…;」两段拼在一起。映射为本地 `audience`，代码一并保留为 `audienceCode`。

浮层里「面向范围」按代码拆行：1 和 3 的分公司名单超过 3 个时先显示前 3 个加「等 N 个」，可展开；3 拆成「年级」「分公司」两行。遇到 0～3 以外的代码，或文字拆不出预期的段，就原样显示 `mxfw`，不猜含义（原型画板 `DescScope`）。
