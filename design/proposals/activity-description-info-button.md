# 活动简介问号入口

## 状态

proposed

## 目标

让用户在活动列表中快速查看学校提供的活动简介、地点、活动时间、报名时间和面向范围，减少为了确认活动内容而反复打开学校网站的需要。

第一阶段面向桌面列表。手机页后续复用同一份详情字段和缓存逻辑。

## 非目标

- 不在活动列表加载时为每场活动自动请求详情。
- 不改变报名资格、报名模式、冲突检查或计划提交逻辑。
- 不在本提案阶段修改学校接口契约或猜测详情字段语义。
- 不把学校返回的富文本直接插入页面。
- 不把手机页和桌面页同时纳入第一阶段实现。

## 方案概述

### 列表入口

在活动名称旁增加一个小型问号按钮。按钮使用独立的 `button` 元素，带有「查看活动简介」的可访问名称。点击问号时阻止事件继续传播，不能触发行选择或整行点击。

### 详情浮层

点击后打开详情浮层，内容按以下顺序展示：

1. 活动名称
2. 活动简介
3. 地点
4. 活动时间
5. 报名时间
6. 活动类型
7. 面向范围

简介正文使用纯文本节点渲染，保留换行，不执行学校返回的 HTML。没有简介时显示「学校未提供活动简介」。详情请求失败时显示「活动简介暂时没同步下来」，不阻止勾选和开始计划。

### 请求与缓存

问号第一次点击时按活动 ID 懒加载详情。当前代码已经有 `GET /rjyHd/getInfo/{activity_id}` 的详情入口和进程内详情缓存，提案复用这条路径，不为列表新增批量详情请求。

详情缓存按活动 ID 保存，活动刷新后仍可复用当前进程内的详情。详情请求失败不写入永久的空简介，后续点击允许重试。

### 数据映射

学校详情样例包含 `hdms`、`hdmxfw`、`mxfw` 等文本字段。正式实现前需要用真实详情响应和学校详情页面逐项核对字段语义，再映射为稳定的本地字段，例如 `description` 与 `audience`。字段语义未核对前不进入实现。

## 待确认问题

- `hdms` 是否就是活动简介正文，`hdmxfw` 与 `mxfw` 分别表示什么。
- 详情浮层采用桌面现有对话框样式，还是复用活动行内展开样式。
- 简介是否需要限制最大高度并提供展开操作。
- 学校详情中的 HTML、图片或链接是否需要保留。第一版默认只显示纯文本。
- 手机页第二阶段是否使用同一详情弹层，还是使用手机 sheet。

## 转入 decisions 的条件

- 通过一次脱敏真实响应核对 `hdms`、`hdmxfw`、`mxfw` 的语义。
- 用户确认桌面问号入口和详情浮层样式。
- 确认详情失败、空简介和长文本的文案。
- 明确桌面第一阶段的验收设备和手机第二阶段的排期。
- 再拆独立实现计划，补详情字段映射、缓存、桌面交互和离线测试。
