# 合回主干前的真窗口验收（2026-11-21）

验收对象：分支 refactor/api-coordinator，报名 worker 三批拆分（报名主流程、提交节奏状态机与取消查目标登录三条命令、学校请求层与日志层）以及偏好写入与条款门下登录卡两处修复之后的状态。源码态用 Python 3.12.9 起窗，组件一项用 tools/release.py --prepare 本地构建的安装版 1.2.3（未打 tag、未上传）。登录用本人账号。

上一轮验收（design/evidence/2026-11-20/api-closeout/README.md 第八节）在三批拆分之前，且其中第 4、5、9 条用演示模式，真实 worker 没有在真实环境跑过；这一轮重点验拆分后的真实 worker 路径，并补上一轮没覆盖的自动重登、重登对话框与组件安装。

## 一、结果

| # | 条目 | 结果 | 看到的现象 |
|---|---|---|---|
| 1 | 命令行冒烟（check、list、grab dry-run） | 部分 | check 通过：登录态有效并输出一行 [clock]（state=ok，偏移约 −0.25 秒，退出码 0）。list 因近期 0 场可报名只打印提示、没有表；grab --pick 1 --dry-run 因 0 个候选直接退出码 0、未进页面。改用一场历史活动 id 跑 dry-run：输出目标、详情页已加载、joined=False 与按钮列表，退出码 0，没有提交。grab.log 有带北京时间的新行。开工时登录态原本已过期（check 退出码 2、学校回 4001），由第 2 项补上 |
| 2 | 浏览器登录 | 通过 | 登录后顶栏变「已登录」。再点登录并中途关浏览器：出现「登录窗口被关掉了」与「再试一次」提示，运行记录有 login_failed、reason=window_closed；随后 check 仍有效，原登录态未被覆盖 |
| 3 | 条款门下的登录卡 | 部分 | 撤回条款后点登录胶囊，卡片显示「暂停检查 / 同意条款后才会检查登录状态」与「查看条款」，点它能弹出条款框。重新同意后的恢复未复验。另见缺陷 1、2 |
| 4 | 自动重登与重登对话框 | 部分 | 把登录态里的 token 改坏后起窗，胶囊、登录卡、主区、右栏与运行记录都显示正在自动登录，约 3 秒后写入新的登录态，check 恢复有效。重登对话框分支未覆盖（走了自动登录）。登录态备份事后已删除 |
| 5 | 真实计划起跑与退出收尾 | 未覆盖 | 真实环境没有开放时间在一小时以后的活动，真实 worker 起跑、关窗三选里的场数与下一批时刻、退出后有无残留进程都没验；演示模式此前测过无问题，不能替代真实 worker 与学校动作 |
| 6 | 真实报名一场 | 未覆盖 | 暂无可报的真实活动 |
| 7 | 组件下载、安装与移除 | 部分 | 安装版安装、重新登录、验证码识别「下载并安装」与装好后再装一次都正常；安装版里点过刷新，冻结版 worker 已跑到。另见缺陷 3 |
| 8 | 回归抽查 | 部分 | 托盘隐藏与唤回、最小化还原（不白屏）、第二次打开唤回第一份（第二份约 0.4 秒退出、退出码 0）都正常。另见缺陷 4 |

构建与测试：发版守卫通过；安装版构建时本机版全量通过，2 个环境性跳过（非 Windows 签名分支、符号链接权限）。

## 二、发现的缺陷与来源判断

四处都不是这条分支引入的——相关代码与 main 逐字相同或这条分支没有改动，判断依据如下。

| 缺陷 | 现象 | 来源判断 |
|---|---|---|
| 1 | 设置里撤回条款后的提示「已撤回同意……」顶格、与上方卡片不对齐、贴底边被裁；revealHelpStatus 只认帮助面板，设置抽屉打开时不滚动 | 文案与 revealHelpStatus 和 main 逐字相同（模块化时原样搬家），样式文件这条分支没改 |
| 2 | 关浏览器后的「登录窗口被关掉了」结果条，在后续登录检查有效后仍常驻 | setResult 与 main 逐字相同，登录编排模块只多了两行 import |
| 3 | 界面没有组件「移除」入口，后端 remove_advanced_feature 前端零调用，原型也没有这只按钮 | main 上前端同样没有调用 |
| 4 | 点「退出程序」后托盘图标残留，右键菜单能弹出但点击无反应（进程已退出的幽灵图标）；托盘停止只投递不等待，托盘线程是守护线程，主进程先退出把它掐断 | 托盘模块这条分支没改，停托盘的代码从 app.py 原样搬到 application/desktop_window.py |

## 三、结论

没有发现回归：拆分后的真实 worker 在登录、登录检查、自动重登、学校请求签名与开页、日志落盘、冻结版刷新这些路径上都按原样工作。没覆盖的是真实计划起跑与退出收尾、真实报名一场、重登对话框三处，原因是近期没有可报的真实活动、登录失效时走了自动登录。四处缺陷都是存量问题，另开计划修。
