# 对话框与横幅画板成对截图（2026-11-08）

1280×800 为基准；CloseAsk、TermsDoc、FirstUse、TermsUpdate 另补 430×820。两侧都用 Edge（Playwright `channel="msedge"`，`device_scale_factor=1`）。文件名 `<画板>-proto.png` / `<画板>-app.png`，窄档追加 `-430`。

原型截图的窗口标题栏是原型自绘的演示 chrome；实现是 pywebview 原生窗口，网页截图不含系统标题栏。两边活动列表、时钟、版本与体积都是示意值或 QA 固定值（原型约 14:20，实现约 20:00），下面不再逐行重复这层差异。

## 逐画板

### 关窗组
- **CloseAsk（宽+窄）**：外框、运行态标题、两条利害清单、三张选择卡与推荐徽章、隐藏禁用原因、「以后都这样，不再询问」均与原型一致；差异仅为系统窗口 chrome 与背景数据。窄档 430 下对话框铺满可用宽度，断行与原型一致。
- **CloseConfirm**：确认步保留利害清单，正文「还没提交的 2 场不会再报名。已经成功的报名不受影响。」与「返回 / 停止计划并退出」两钮一致；差异同上。
- **CloseHidden**：未截图。实现没有可比的隐藏态画面；改用后端测试证据（见下「CloseHidden 的 BE2 证据」）。
- **CloseIdle**：无利害清单、隐藏卡禁用并写「现在叫不回来：…」、退出卡强调登录状态保留，均与原型一致；差异为背景数据。
- **CloseLive**：主界面 + 运行中计划（LED 倒计时、修改/停止计划、逐场任务卡、运行记录）与原型同构；差异为无自绘 wbar/系统窗口 chrome，任务列表与时刻是 QA 注入值。

### 更新组
- **UpdateAvail**：版本块、安装包体积说明、「下载并安装」动作与原型一致。**断行差异（已修复）**：体积说明原先折成两行、末行只剩「装」一个汉字；现用不可见的 U+2060 把「安装」连住，末行至少是两个字（原型一行，实现宽度更窄所以仍折行）。本图已按修复后重拍（数据为 QA 示意值）。另有「检查时间」独立成行（原型与状态行同行），标题行实现多出「当前」。
- **UpdateDown**：进度条与右侧「取消下载」均正常显示（aria-valuenow=41、填充 41%），状态行与「已下载 37.9 / 92.4 MB（41%）」一致。2026-11-08 视觉验证发现原实现因进度条容器缺 `id="update-progress-bar"`，`paintUpdate()` 在 views/update.js:103 抛 TypeError、界面停在半绘制态；当日修复，本次复测通过（无异常、进度条与取消下载均出现）。
- **UpdateFail**：红色「更新没有完成。」、哈希失败专句、错误框与「重新下载」钮一致；差异为「检查时间」独立成行。
- **UpdateLive**：常驻「检查更新」态与原型一致；原型里的「演示：下一次检查的结果」下拉按既定口径不实现，实现没有该控件。
- **UpdateReady**：绿色校验通过、黄色警示独立成块、安装向导句、「仍然启动安装程序」一致。**断行差异（已修复）**：警示句原先把「建议」拆到两行；现 U+2060 连住「建议」，两字一起折到下一行。本图已按修复后重拍。另有检查时间独立成行。

### 引导组
- **TourTable**：第 1 步文案、遮罩、高亮框、上一步禁用一致。**结构差异**：实现卡片落到底部居中（`is-bottom`），原型贴在目标右侧上方；卡宽 340px，原型 352px。
- **TourPick**：第 2 步文案、interactive 放行一致。**差异**：实现高亮第一行可勾选活动（当前开放的 19:58 行），原型指定 14:30 预报名行；卡片在高亮框下方，原型在右侧。
- **TourRun**：第 4 步文案、LED 高亮一致。**差异**：实现卡片叠在 LED 下方并遮住部分计划栏，原型卡片在 LED 左上方；QA 数据让计划栏出现「要等到明天 20:00…」与「仍然开始报名计划」，原型没有这句。

### 首次使用
- **FirstUse（宽+窄）**：六条要点、脚部勾选/暂不使用/同意并继续、38rem 外框与原型一致。**焦点框（已修复）**：标题仍是焦点落点（读屏照读），已不再画蓝色焦点框，宽窄两档图均已按修复后重拍。**差异**：背景顶栏显示「等同意条款」而原型为「未登录」，空态文案也不同；窄档结构一致。

### 条款组
- **TermsDoc（宽+窄）**：外框、页签、脚部（勾选/暂不使用/同意并继续）与原型一致，正文可见。2026-11-08 视觉验证发现打开阅读器时 `#dlg-terms-full-text` 仍带 `hidden`（index.html:144）导致正文空白；当日修复（`resetTermsReaderView()` 打开时取消隐藏），本次复测通过（宽档正文 2949 字、540px 宽；窄档 360px 宽，均可见）。2026-11-09 用户验收反馈两处排版：左侧目录顶贴上边、标题未靠左；已改为目录首行与右侧版本行同一水平线、标题贴站牌左边（删 2026-10-30 的居中偏移），本图已按修复后重拍。仍有内容差异：原型是简版章节，实现是 r5 全文十章。
- **TermsPrivacy**：页签切到隐私、只读状态行、隐私正文与「关闭」钮均正常。2026-11-08 视觉验证发现与 TermsDoc 同因的正文空白；当日修复，本次复测通过（隐私正文 2222 字、540px 宽可见）。2026-11-09 同批排版修复（目录与版本行同线、标题靠左）后重拍。另：只读态脚部左侧仍显示「暂不使用后：…」说明，原型只读态没有这句（此差异保留）。
- **TermsOff**：横幅「使用条款更新了，还没有同意新版。」、顶栏「等同意条款」、计划栏停用与开始按钮禁用一致。差异：列表上方提示实现为「8 / 8 场没同意条款，停在上次的结果，可能过时」，原型是「这次是上次的活动缓存…」；背景数据不同。
- **TermsUnknown**：横幅「条款状态没能确认…」、运行记录与学校动作停用一致。差异：实现列表为空（条款未知时不加载），原型显示上次缓存的 11 场；运行记录时间戳是「待校准」——该日志在 boot 里早于 `ingestBusinessClock` 生成，之后时钟已同步也不会回填（原型是正常时间）。
- **TermsUpdate（宽+窄）**：外框、版本副题、变更清单、脚部（看完整条款/暂不同意/同意新版条款）一致。差异：实现列 4 条 r5 真实变更，原型列 6 条示意变更；版本号 r5 对 r4；焦点框配色不同；窄档横幅折成两行，原型一行。
- **TermsWithdraw**：设置抽屉条款区、红色确认块与「先不撤回 / 确认撤回」一致。差异：实现条款行多出「当前条款版本 …；」前缀（值为真实版本与同意时间）；抽屉上方可见分组（验证码识别）与原型不同。

### 帮助与迁移
- **HelpKeys**：三步说明、五种快捷键、脚部「重看引导 / 知道了」一致；差异仅「重看引导」带焦点框。
- **Migrated**：note 档横幅「已把旧版本的数据搬到新位置…」与「知道了」一致；差异为背景数据，运行记录最后一行被刷新结论占据（原型最后一行是迁移句）。
- **MigrateFail**：警示档横幅与「登录」钮一致（仅登录文件没搬过来的那一种；另两种结果的文案见 `docs/UI_SPEC.md`，未单独截图）；本图已重拍，运行记录最后一行现在就是迁移句；按原型把登录态置为未登录、列表置空后，顶栏「未登录」与空态结构也对上。

## CloseHidden 的 BE2 证据

按计划执行 `python -X utf8 -m unittest discover -s local/tests -p "test_application_services.py" -k "notify" -v`：2 例通过（`test_tray_notify_without_icon_returns_false`、`test_hide_window_survives_a_failing_tray_notify`）。该关键字匹配不到核心用例名（`notif-ies` 不含 `notify`），另跑 `-k "hide_window"`：3 例通过。

- `test_hide_window_notifies_the_tray_once`：`hide_window()` 返回 ok，`notify` 恰被调用一次，标题「窗口已隐藏，工具在后台运行」、正文「报名计划照常运行。点右下角托盘图标回来，也可以在手机页点“显示电脑窗口”。」逐字与 CW10 一致。
- `test_hide_window_without_tray_skips_the_notice`：无托盘时不弹、不抛，隐藏成功且回包 `tray` 为 false。
- `test_hide_window_survives_a_failing_tray_notify`：`notify` 抛错被吞，隐藏仍成功、`window.hide` 调用一次。
- `test_tray_notify_without_icon_returns_false`：没有托盘图标时 `notify` 返回 false，不抛异常。

## 复现命令

```bash
# 原型静态服务（仓库根）
python -X utf8 -m http.server 8790 --bind 127.0.0.1 --directory design/prototype/workbench-2026-11
# 实现静态服务（仓库根）
python -X utf8 -m http.server 8791 --bind 127.0.0.1 --directory local/ui
# 截图脚本临时写在系统临时目录（%TEMP% 下，不进仓库），用 Playwright(msedge) 运行
python -X utf8 %TEMP%\<截图脚本>.py
```

- 宽档原型直接打开 `http://127.0.0.1:8790/<画板名>.dc.html`，1280×800，`networkidle` 后再等约 800ms。
- 窄档原型没有现成薄壳：按 `Narrow.dc.html` 同构在临时目录生成 430×820、`tier="narrow"` 的薄壳（同一 Main 与 scene），经路由以同源 URL 返回，不写进仓库。
- 实现侧用 Playwright 路由改写 `index.html`，在 `app.js` 前插入 `local/tests/fixtures/runtime_bridge.js`；用 `__QA_STATE` / `__QA_BOOTSTRAP_EXTRA` 造 bootstrap 状态，`__QA_EMIT` 推 `window_close_ask`，设置抽屉调 `openSettings('prog')`，条款调 `openTermsReader/openTerms`，迁移走 `bootstrap.migration`。截图前等 `networkidle` + 700–1100ms，`<dialog>` 先确认 `open === true`。
