## 拍摄方式

```bash
python local/app.py --demo        # 界面本体
```

驱动脚本不在仓库里：它自己起 `--demo` 进程，用 `evaluate_js` 调界面的
`toggleSelection` / `startPlan`，再用 `PrintWindow(PW_RENDERFULLCONTENT)` 取窗口像素。

为了让「运行中」「部分成功」这两支状态当拍得到，脚本在**驱动进程内存里**做了两处调整，
仓库代码没动：

- 样例数据里 `demo-workshop`、`demo-career` 的报名开始时间挪到 1 分钟前（原本在 30 分钟后开放）
- 演示 runner 的 `time.sleep` 放慢 15 倍，否则每场 0.2 秒就跑完，抓不到中间态

## 这些图能证明什么

- 1280×820（出厂几何）下三栏的实际密度、LED 大屏与计划条的排版、列表行的信息量
- 1280×720 短窗可正常渲染，无横向溢出、无控件被裁（会命中 `max-height:720` 档）
- 多场并发时每场结果独立显示，部分成功的文案是「报名未成功」而不是整体失败

## 不能证明什么

- 不是真实运行：时间是演示时间，账号状态是演示态，没有真实报名结果
- 没有覆盖「已开始但报名仍开着」的真实页面（见 `README.md` 第 2 项）
- 没有覆盖登录失败、组件缺失、时钟不可用这些横幅态
