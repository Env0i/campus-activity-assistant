## 通用规则

1. **每条都带 `文件:行号`**，路径从仓库根写起。一段代码写起始行；需要范围时写 `起-止`。
2. **事实和判断分开**。事实是「代码里这一行这么写」；判断是「所以会怎样」「建议怎么改」。清单里判断放在单独的列或单独的小节。
3. **推测要标「推测」**。没有顺着代码读到底、只是从命名或注释推出来的，一律标。读到底的标准：能指出每一步的行号。
4. **不写**主机路径、真实站点地址、账号、学校数据。
5. **范围**：`git ls-files` 里 `local/`、`server/`、`tools/` 下的 `.py`、`.js`、`.mjs`。`local/tests/`、`server/tests/`、文件名以 `test_` 开头的脚本算测试，单独统计。不读 `local/data`、`server/data`、两份 `config.json`、`local/_site_build.py`、`.env`、登录态和凭据。
6. **严重度**（只用于判断列）：
   - **高**：现在就会让用户看到错的状态或挡住操作；或者改这一处必然要同时改三处以上。
   - **中**：特定时序或少见路径下出错；或者改这一处要同时改两处。
   - **低**：不出错，只是难读、难测或挡并行。

## C1 代码问题清单的四类

### ① 重复的规则

**算重复**：同一件业务事实在两处以上**各自实现**，而不是一处定义、别处调用。三种形态：

- **同一判断**：两段条件表达式判定的是同一件事（例如「登录算不算失效」「这场能不能勾」），输入字段相同或一一对应。
- **同一张映射表**：两张表的键有一半以上重合，值表达同一含义（例如错误码 → 中文原因）。
- **同一段文案**：8 个汉字以上逐字相同，或只差标点、称呼。

**三个比对范围**：Python 与 JS 之间；桌面（`local/ui/`）与手机页（`local/ui/m/`）之间；前端各文件之间。`local/` 与 `server/` 各有一份学校知识是既定架构（见 `AGENTS.md`），只列出不算问题。

**不算**：测试里复述的期望值；`index.html` 的静态文案与 JS 里同一元素的初始文案（同一元素只算一处）；照原型逐字的文案在原型和代码各一份。

**每条写**：各处位置、差在哪（逐字相同 / 语义相同写法不同 / 已经不一致）、有没有测试比对（给测试名）、有没有运行时同源覆盖（例如 `bootstrap` 下发后覆盖前端默认值）。

### ② 跨层调用

**后端**（`local/`）。层按目录定：`domain/`、`application/`、`infrastructure/`；其余顶层模块（`app.py`、`grab.py`、`signup_plan.py` 等）记为「顶层」。允许的 import：

| 从 | 可以 import |
|---|---|
| `domain/` | 标准库、`domain/` |
| `application/` | 标准库、`domain/`、`application/` |
| `infrastructure/` | 标准库、`domain/`、`infrastructure/` |
| 顶层 | 都可以 |

其余都记为越界，函数体里的延迟 import 也算。另外单独列出 `test_layer_boundaries` 的黑名单**没拦到**的写法（它只拦 `domain/`、`application/` 对一份具体模块名单的 import）。脚本 `scripts/py_layers.py` 用 `ast` 数。

**前端**（`local/ui/`）。层按目录定：`state/`、`views/`、`controllers/`、根目录（`app.js`、`led.js`）。算越界的：

- `state/` 的文件引用了 `views/`、`controllers/` 或 `app.js` 定义的名字。
- `views/` 的文件引用了 `controllers/` 或 `app.js` 定义的名字（`docs/ARCHITECTURE.md` 写的是 views 不发桥接请求，所以 `api()` 也算）。
- `views/` 的文件改写了状态仓库 `S` 以外的全局变量。
- 另列事实、不算越界：`views/` 里直接写 `S` 的位置（供定状态机时看谁在写）。

「引用」的量法见 C2。手机页只有一个文件，不分层，只在 C2 里列。

### ③ 超大文件与函数

- **文件行数**：物理行（含空行和注释）。
- **Python 函数与类**：`ast` 的 `end_lineno - lineno + 1`，从 `def` / `class` 那一行量到最后一行，不含装饰器，含文档字符串、空行、注释。嵌套函数单独算一条，同时也计入外层。方法名写成 `类名.方法名`。
- **JS 函数**：自写的词法扫描（`scripts/jslex.mjs`）跳过注释、字符串、模板字符串和正则字面量后做花括号配对，从函数头所在行量到配对的 `}` 所在行。计入的函数：`function` 声明与表达式、带花括号体的箭头函数、对象字面量与类里的方法简写、getter 和 setter。嵌套函数单独算一条，同时也计入外层。
- **JS 量法的误差**：
  - 表达式体的箭头函数（`x => x + 1`）不计，所以短函数被少数了，分位数会偏大。
  - 正则字面量靠「前一个记号是不是值」来判断，极少数写法可能判错；脚本在每个文件扫完后核对括号是否配平，不平就报出来。
  - 匿名函数用「赋给谁」或「是谁的属性」起名，起不出名字的记作 `<anonymous@行号>`。
- **分位数**：最近秩法（第 `ceil(p×n)` 个）。分四组各出一份 P50 / P90 / P99 / 最大值：产品 Python、产品 JS、测试 Python、测试 JS。再列出每组超过本组 P99 的函数。
- 脚本：`scripts/measure.py`（JS 部分调 `node scripts/jsfuncs.mjs`）。

### ④ 隐式状态

指「不在明面的状态仓库里，却会影响显示或放行」的可变量。三种：

- **Python 模块级可变全局**：满足任一条即算。(a) 某个函数里用 `global X` 声明并赋值；(b) 模块级名字绑的是容器或对象，并且本模块里有对它的原地修改（下标赋值、`del`、`.append` `.update` `.add` `.pop` `.clear` `.setdefault` `.remove` `.discard` `.extend` `.insert`）。只读的常量表不算。
- **`Api` 实例上的标志位**：`local/app.py` 的 `class Api` 里，`self._xxx` 被赋值（`=`、`+=`、带注解赋值）的**方法数不少于 3 个**（`__init__` 算一个；方法里的嵌套函数算在所在方法头上）。另列「容器内修改」（`self._x[k] = …`、`self._x.append(…)` 一类）的方法数，不计入门槛。每个写清在哪些方法里写、在哪些方法里读。
- **前端状态仓库 `S` 以外的可变全局**：桌面端各文件顶层的 `let` / `var`，以及顶层 `const` 对象里被别处赋值的属性（例如 `PhonePanel.installing`）；手机页是 `local/ui/m/app.js` 里 `if (typeof document !== "undefined") { … }` 这一层的 `let` / `var`，以及这一层 `const` 对象（实际是 `model`）被改写的字段。每个写清写的位置和读的位置。

脚本：`scripts/py_state.py`、`scripts/globals.mjs`。

## C2 前端全局依赖表

- **加载顺序**：从 `local/ui/index.html` 的 `<script src>` 读，手机页从 `local/ui/m/index.html` 读。
- **定义**：文件顶层（花括号深度 0）的 `function` 声明、`const` / `let` / `var` 声明，以及 `window.X = …`、`globalThis.X = …`。
- **引用**：别的文件里出现同名标识符，并且不是属性访问（前面不是 `.`）、不是对象字面量的键（后面不是 `:`，三元表达式里的除外）、不在注释和字符串里。模板字符串的 `${…}` 里面算。
- **误差**：按名字匹配，不做作用域分析。函数的参数或局部变量如果和别的文件的全局同名，会被多数成一次引用；脚本把「本文件内有同名局部声明」的引用单独标出来，清单里只用没有同名局部声明的。经 `window["名字"]` 这类字符串访问的数不到。
- **循环依赖**：文件级。A 引用 B 定义的名字记一条 A→B 的边，对这张图求强连通分量，多于一个文件的分量就是一组循环。
- **高扇入**：一个名字被 5 个及以上的**其他**文件引用。
- **手机页**：只有一个脚本文件，没有文件间依赖。改列 `PhoneModel` 的成员数、文档块内的函数数和可变量，供拆模块时参考。

## C3 `app.py` 再导出表

- **模块级名字**分三种：`app.py` 自己定义的（`def`、`class`、字面量赋值）；**别名**（`X = _模块.名字` 或 `X = 模块.名字`）；**import 进来的名字**（`import x as y`、`from x import y`）。
- **测试怎么用**：在 `local/tests/` 和 `tools/` 里数这些写法，接收者限于「绑到 `app` 模块的名字」（`import app`、`import app as X`、`from local import app`）：
  - `patch.object(app, "X", …)`、`patch("app.X", …)`、`setattr(app, "X", …)`、`app.X = …` 记为**打补丁**。
  - 其余 `app.X` 记为**读取**。
- **拆 `Api` 时必须保住的**：被打补丁的模块级名字（不论哪一种），以及被测试读取的别名和 import 名。
- 脚本：`scripts/app_reexports.py`。

## C4 界面状态清单

- **状态**：会改变界面显示或决定某个操作能不能做的变量。包括 `S` 的字段、`S` 以外的前端可变量、拿 DOM 当存储读回来的（`dataset`、`classList`、`hidden`），以及后端 `Api` 的 `self._xxx` 和服务对象里进快照或事件的字段。
- **进口**：把状态写成「进行中」或「非默认值」的每一处。
- **出口**：把它写回空闲或默认值的每一处。
- **退出路径**，逐条对：
  1. 成功
  2. 失败（后端回了失败）
  3. 异常（Promise reject、后端抛异常、worker 崩）
  4. 超时
  5. 用户取消、关对话框、放弃
  6. 窗口关闭、隐藏到托盘、最小化再恢复
  7. 后端先结束（worker 退出、计划自然结束、下载被别的入口收掉）
  8. 迟到的或重放的事件（旧请求的回执、`bootstrap` 重放）
- **「没清」**：存在一条走得通的代码路径，走完后状态还停在进行中，而且没有别的代码会兜底清掉它。要给出这条路径每一步的行号。只凭怀疑的写「推测」。有兜底（例如下一次轮询会改正）的写明兜底在哪、多久生效。
- **每个等待中的操作**另答三问：有没有「进行中」显示；失败有没有显示；失败后用户能不能重试（按钮在哪）。
- **功能分节**：登录与重新登录；组件；版本更新；活动列表刷新；报名计划栏；手机页。
