# 017 · 界面翻新：时间轴卡片、活动类型、活动简介与口语文案

- **状态**：implemented（1.3.0 已发布；2026-11-26 用户看过真实窗口并结合目标用户实际使用反馈完成收尾；仍留数项原型边界未进代码，见「已知限制」）
- **日期**：2026-11-24
- **上游**：[决策 014](014-workbench-ui.md)（工作台职责与窗口分档）、[决策 016](016-conflict-visibility-and-cancel.md)（冲突可见、跨天时段与取消规则）；原型快照 [design/prototype/workbench-2026-11/](../prototype/workbench-2026-11/README.md)

## 问题

1. 旧列表单行信息拥挤，活动名、地点、签到签退与状态标签混在一起，窗口稍窄或手机端不易扫读。
2. 列表只看标题和地点看不出活动介绍和面向范围，用户仍需频繁切回学校网页核对。
3. 设置抽屉说明文字过多、「登录 / 自动登录」散在多个卡片，状态过渡与横幅能否收起缺乏统一规则，部分界面句式偏公文腔或前后重复。

## 用户确认的规则

1. **时间轴列表与四层卡片**（不改现有分组顺序 `groupTimetable`、排序、`missedBySleep` 错过了判定与「不可加入」冲突规则）：
   - 左侧竖线按开放时刻设节点；同一批尚未开放的节点挂 2 场及以上时标「同抢 N 场」（已开放、已报名、已截止的节点不写）；「已报名」「已截止」两组不画竖线和节点，卡片直接排列；「现在 HH:MM」分隔已开放与未开放；节点四态为已开放（实心橙）、下一批（琥珀带光圈）、等待（空心灰）、待公布（虚线）。
   - 卡片固定四层，日期统一 `MM-DD`：第一层为勾选框、活动名、`?` 简介按钮与右上汇总奖励；第二层为活动类型标签、报名模式、退报规则（未知时不写）、截止时刻与右侧倒计时/下一场标记；第三层固定「举办、地点、签到、签退」四格，按列表容器宽度 `@container` 在 `45rem` 处切换一行四格与两行两格（不按窗口整体宽窄切）；第四层按需显示时间重叠警告、睡眠错过原因、待公布锁提示与取消操作区。
   - 窄档（`< 720px`，含手机页 `local/ui/m/`）时间轴竖线贴左、开放时刻挪至节点上方，第二层不换行，截止时间放不下时用省略号截断，不显示「下一场」标签，第三层固定两行两格。
2. **活动类型标签与多选筛选**：卡片第二层显示小方点加活动类型文字（`type` 缺失归「其他」，过长省略并悬停见全名）；桌面「更多筛选」增加「活动类型」多选组，选项取「当前列表出现过的类型」与「当前已选但暂不在列表里的类型」的并集排序，一项都不选等价于不按类型筛选。
3. **活动简介 `?` 入口与详情浮层**（第一阶段面向桌面，不改变报名资格与冲突逻辑）：
   - 卡片活动名旁放独立 `?` `button`（可访问名称「查看活动简介」），点击阻止事件冒泡，不触发行选择；复用列表既有 `getInfo` 字段映射 `description`（`hdms`）、`audience_code`（`hdmxfw`）与 `audience`（`mxfw`），不另起批量详情请求，每次列表刷新带回新结果。
   - 浮层按「活动名称标题 + 类型·所在分组副标题 → 关键事实（两列活动时间/地点、整行报名时间/面向范围）→ 纯文本简介正文」顺序展示，关键事实在前、长简介不挤走关键判断；超过 160 字默认限高并可展开/收起；学校未提供（空串 `""`）显示「学校未提供活动简介」，详情未同步（`null`）显示「活动简介暂时没同步下来」并提供受刷新忙态互斥控制的「重新获取」按钮。
   - **面向范围拆分**：`audience_code` 为「从 40 场样本归纳的 0 到 3，不是官方字典，未知代码原样显示文字」；按 `0`（全校类原文）、`1`（限分公司）、`2`（限年级）、`3`（拆分年级与分公司两行）渲染，代码 `1`/`3` 分公司超过 3 个默认显示前 3 个加「等 N 个」并可展开；`description` 与 `audience` 仅使用 `textContent`/文本节点写入，绝不传入 `innerHTML`。
4. **设置抽屉重组与组件状态过渡**：
   - 登录组改为「失效后自动登录 · 还差 N 步」二步清单（第 1 步保存账号密码，第 2 步验证码识别），全部就绪时写「已就绪」；程序组五项（「关闭窗口时」「版本与检查更新」「本机数据」「条款与隐私」「飞书提醒」）合并进同一张设置卡片各占一行，路径等细节收进展开区。
   - 高级功能行与组件状态同位按「灰（没装/没开）、蓝（进行中）、绿（能用）、琥珀（需留意/超时/等连接）、红（坏了）」切换圆点、状态字与主按钮；点阵倒计时琥珀色仅表示时间，不表示警告；组件等锁检查超过 30 秒时给出「重试」按钮并写出「另一个窗口正在安装或更新组件，已等 30 秒」；「坏了」主按钮改为「重新安装」（与「没装」共用下载安装路径，导入兜底收进展开区）；取消下载回到未装态、安装失败回退安装前状态并写红字说明；手机访问 2 分钟无访问显示「已断开 · N 分钟前」；设置内联提示带 `×` 关闭按钮。
5. **列表加载刷新与顶部横幅闭环**：
   - 首次无列表加载出 3 行时间轴骨架；已有列表刷新保留旧行与勾选，顶部出细进度条；刷新失败保留旧列表与勾选并在列表上方给出内联失败提示配「重试」（不弹全局横幅）；顶栏状态采用过渡与刷新后 1.5 秒「已更新」打勾褪回；顶栏登录胶囊覆盖「要你输验证码」「登录已失效 · N 分钟后再试」「已登录 · 正在确认」等态。
   - 顶部横幅分三类：一次性通知（「知道了」关掉本次不再出现）；可收起持续状态（「主修复动作 + 收起」，收起仅记内存并在顶栏保留提示点——北京时间收起态写「北京时间待校准」；顶部换成另一种问题，或点开对应的顶栏状态卡时重新出现）；不可收起硬门禁（条款未同意、组件/运行环境出错）。
6. **口语化文案与短句红线**：
   - 全工具 6 块区域桌面与手机共用紧凑短句词表，日期前缀统一 `MM-DD`；不删除事实判断与风险披露（如名额已满非工具故障、待核对、报后不可退、100 秒内来不及等）；不用「勿、此、即刻、非、曾、期间、关乎」等公文字，保留防误会否定句（如「这不是登录问题」）；横幅标题 ≤ 10 字、说明 ≤ 28 字，设置副标题 ≤ 24 字。现行逐字以代码与 [copywriting.md](../specs/copywriting.md) 为准，历史对照表留存 git 历史。

## 用户可见行为

- 打开活动列表先见竖线时间轴与四层卡片，类型与退报规则一眼可辨；点活动名旁 `?` 先看到时间、地点、报名时间与面向范围，再看纯文本简介。
- 刷新已有列表时不闪烁、失败时不丢勾选；顶部一次性提示点「知道了」，持续性提醒可点「收起」并在顶栏留提示点。
- 设置抽屉不再堆砌长段文字，自动登录前提以「还差 N 步」二步清单引导，程序设置集中在一张五行的卡片内；组件检查卡锁超 30 秒会出现「重试」。
- 手机页同步呈现竖线时间轴与紧凑四层卡片，文案节奏与桌面统一。

## 已知限制

- **手机页简介浮层（二期）**：手机页 `local/ui/m/` 第一阶段仅落时间轴与四层卡片，尚未实现 `?` 按钮与详情浮层。
- **自动登录失败告知渠道未落地**：[自动登录失败告知提案](../proposals/auto-relogin-failure-notice.md) 仍为 `proposed`；当前仅桌面顶栏胶囊（`要你输验证码` / `登录已失效 · N 分钟后再试`）与顶部横幅提示，后台托盘气泡、专用飞书失败提醒或手机联动提示尚待确认与实施。
- **「安装程序没出现？」次要按钮未落地**：原状态机第 10 批第 7 项拟在启动安装程序后提供回退按钮，`local/ui/views/update.js` 在 `launching` 且已启动时仍只显示「关闭本工具…」（仅启动失败时切到失败态允许重试）。
- **手机页重登 6 句新提示未全量替换**：`local/ui/m/` 暂保留既有登录提示句式，未完全对齐提案第 10 批第 9 项的 6 句逐字稿。
- **面向范围代码非官方字典**：`0..3` 系从 40 场样本归纳，遇到新增或未知代码时原样显示学校文字，存在解析降级为整段的可能。
- **提案原文见 git 历史**：合并迁入本决策的三份提案原文见提交 `899218a` 及之前版本的 `design/proposals/workbench-ui-polish.md`、`design/proposals/activity-description-info-button.md`、`design/proposals/copy-simplification.md`。

## 变更方式

- 改时间轴、简介浮层、设置卡片、横幅收起或文案词表：先同步 `docs/UI_SPEC.md` §5.22–§5.25 与 `design/specs/copywriting.md`，再改 `local/ui/` 对应模块与 `local/tests/screens/test_ui_contracts.py`、`test_ui_components_and_phone.py` 等行为/契约用例。
- 若补充手机页简介浮层、自动登录失败渠道或更新启动回退按钮，落盘后同步更新本决策与「已知限制」。
