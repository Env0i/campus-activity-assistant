# 014 · 新工作台：时刻表与计划栏

- **状态**：confirmed（用户 2026-11-02 批准设计；代码未落地，实现见计划 `20261103-ui-b-core`，标志与契约为 `20261103-ui-c-finish`）
- **日期**：2026-11-02
- **问题**：旧界面是一块「大屏 + 时刻表」，同一块大屏在引导、草稿、运行和结果四个阶段换含义，状态混乱；窗口一矮，大屏先把时刻表挤没；帮助入口又塞了高级功能、更新与条款，用户找不到。

## 用户确认的规则

以下规则来自[新工作台设计](../../docs/superpowers/specs/2026-11-02-workbench-ui-redesign-design.md)第 3～6、11 节，原型快照为 `design/prototype/workbench-2026-11/`（版本 32）。

1. **分工**：时刻表只负责「有哪些活动、勾选哪些」；计划栏只负责「这次计划现在处于哪一步、下一步做什么」；顶栏只放状态和三个入口（刷新、设置、帮助）。
2. **窗口分档**：宽（宽 ≥ 1040）时刻表 + 25rem 计划栏并排；中（720–1039）只显示时刻表，底部一条计划条（已选几场 + 查看计划 + 开始），顶栏按钮只留图标；窄（< 720）同中档，再收起「北京时间」字样、搜索框缩短、详情卡铺满；矮（高 < 660）点阵屏缩到 13rem，计划栏内部可滚动，主按钮固定底部。中、窄档有计划条且有开始前提醒时，不给「开始」，只给「查看计划」并写「有 N 条提醒，开始前先看一眼」。
3. **顶栏状态**：北京时间沿用决策 012 五态；登录胶囊只显示「已登录 / 自动登录中 / 登录已失效 / 暂时无法确认 / 没有登录 / 正在登录 / 等同意条款」和上次校验时刻，不显示剩余时间、不提示「临近失效」；手机标识只在手机访问开启时出现。三个状态都是按钮，悬停约 0.2 秒出详情卡，点击固定，Esc 关闭；窄档卡片铺满并去掉指示箭头。
4. **时刻表**：按开放时间排、按天分组（正在开放 / 今天 / 明天 / 后天 / N 天后 / 待公布），「现在」线分开已开放与未开放；每行有勾选框、开放时刻、活动名、报名模式标签、举办时间、签到签退、地点、距开放；活动名和地点最多两行，悬停看全文；举办时间重叠的行写明与哪一场冲突，与已报名活动冲突的不能勾选；列表上方写「N / M 场」与新鲜度，没加载时不显示场数或新鲜度；睡眠错过开放的场次标「错过了」，可以重新勾选。空态分四种，不能混用：筛选后为空 / 学校返回 0 场（写明「这不是登录问题」）/ 列表没加载（写原因并只给一个对应动作）/ 程序组件缺失（不放第二个按钮，看顶部横幅）。
5. **计划栏阶段**：

   | 阶段 | 点阵屏 | 主动作 |
   |---|---|---|
   | 草稿·没选 | 暗屏「暂时没有目标」 | 开始（禁用，写「还差一步：先在时刻表勾选活动」） |
   | 草稿·已选 | 下一批开放倒计时 | 开始报名计划 |
   | 草稿·有提醒 | 同上 | 仍然开始报名计划 |
   | 等开放 | 琥珀倒计时 | 修改计划、停止计划 |
   | 修改中 | 琥珀倒计时 | 重新开始计划、放弃修改 |
   | 提交中 | 红色倒计时到本次尝试截止 | 停止计划（修改计划禁用并写原因） |
   | 结果 | 只显示不为 0 的结果大数字 | 重新选择未成功的场次（有可重选的才显示）、完成回到活动列表 |

6. **修改计划**：等开放时可用，复用停止与重选，不改报名调度；提交中或开放前 100 秒内不可用；修改期间明确写「计划已暂停，改完要重新开始」。
7. **开始前提醒**只提醒不拦，列在计划栏：断网；北京时间在用上次校准结果；最晚一场要等 1 小时以上、又没开全自动登录（没保存账号带「去保存」，没装验证码识别带「去安装」，并写明开放前 100 秒内失效的场次会直接结束）；尝试时长选「直到报名截止」但有场次没给截止时间；有场次 24 小时以后才开放（按最晚一场算，旧界面按最早一场，有意改的）。
8. **运行中登录失效**：等开放、离开放还有 100 秒以上时计划不停，能自动登录就自动登录；不能自动登录的写「HH:MM:SS 前重新登录，计划照常继续；来不及的话，HH:MM:SS 开放的那批会以『登录失效』结束」。开放前 100 秒内和提交中只做自动登录，不能自动登录的场次以「登录失效」结束；点「重新登录」只说明「现在来不及重新登录」。重新登录成功后，运行记录和手机页都写「报名计划照常继续」。
9. **提交方式与结束结论**：每场准备好后写明「直接提交，不经过活动页」，或琥珀色「改用页面点击：原因。活动页已提前打开」；报名成功写明结束时向学校核对过；名额已满是中性色的结束结论，不算工具失败，不放回「重新选择未成功的场次」；时间冲突、报名已截止、活动不存在、登录失效、本机时钟有问题用红色「报名未成功」加原因；全部名额已满时标题写「这次没报上：名额满了」，不用红色。
10. **待核对**：每场结束时工具已用 `getJoinInfo` 向学校核对一次，核对也没拿到结果才是待核对；「刷新核对」这一轮先刷新活动列表、看该场 `signed`（单场 `getJoinInfo` 入口还没有，2026-11-03 拆计划时定）：学校列表显示已报名就改成成功；还没显示时写明列表可能有延迟、请去活动页看一眼；工具不会自动重发。
11. **计划来源与后台结束**：从手机开始的计划，计划栏底部写「这个计划是从手机开始的，在电脑和手机上都能看进度、停止」；窗口最小化或隐藏时计划结束，发系统通知（N 场成功、N 场待核对、N 场名额已满、N 场没成功），点通知回到窗口。
12. **横幅**一次只显示一条，优先级：程序组件缺失 > 条款未同意 > 断网 > 电脑刚睡眠过 > 登录问题 > 北京时间问题。
13. **新手引导**与 **设置 + 帮助分工**：五步引导的启动时机与内容版本见[决策 009](009-replayable-product-tour.md)修订；设置与帮助的分工见[决策 011](011-unified-help-and-manual-update.md)修订；高级功能的下载与资产形态见[决策 010](010-standalone-exe-and-settings.md)修订。
14. **视觉与用词**：字体配色沿用旧界面；浅色底主按钮统一墨黑，蓝色只用于选中、链接、焦点，琥珀只在深色底当按钮，红色只用于危险动作与失败；主要文字对比度 ≥ 4.5。用词：重新登录 / 自动登录 / 刷新 / 报名计划 / 待核对 / 直接提交 / 页面点击 / 名额已满，不再用「重登」「刷新状态」「直发」「没抢到」。

## 用户可见行为

- 顶栏始终只有刷新、设置、帮助三个入口；时间、登录、手机三个状态都能点开看详情并就近恢复，不再把恢复动作散在大屏里。
- 勾选活动后计划栏才出现可用的「开始报名计划」；没勾选时按钮禁用并写明还差一步。选中不等于开始，停止不等于取消学校报名。
- 计划运行中，计划栏按阶段显示倒计时、路线图、每场提交次数和最近回应；改用页面点击的场次写明原因。
- 结束以后只显示不为 0 的结果；名额已满单独一类且不回填到「重新选择」；待核对场次可打开活动页或刷新核对。
- 窗口变窄或变矮时，关键操作不被挤掉；中、窄档先看计划条，再决定开始。
- 手机页与电脑同一套阶段和说法；手机只能停止计划，修改要回电脑。

## 已知限制

- 设计文档第 13 节的待定项原样保留：验证码是否区分大小写未确认；条款措辞需用户或法务过一遍。
- 仍缺材料：真实 404/429、性别不符时的回包、同学首次使用的卡点；界面先按「没见过的回包」处理。
- UI 代码未落地：本决策只记录规则，`local/ui/` 仍是旧大屏；实现与验收在 UI-B/UI-C。
- 真实学校下的完整验收（窄窗、矮窗、150% 缩放、真实开放瞬间、后台通知）仍需用户完成。
- 候补入口等架构方案第 6 节开工再画，条款到时再升一版。

## 变更方式

- 改布局、阶段表、提醒或横幅优先级：先改设计文档，再同步本决策、`docs/UI_SPEC.md` 与原型快照。
- 改界面：`local/ui/`（views/controllers/state）与 `local/ui/m/styles.css` 等手机页资源；同步 UI 契约测试，旧大屏断言不保留。
- 改状态来源：只允许来自 `bootstrap`、`onBackend` 事件、`phone_access_state`、`advanced_features_state` 与业务时钟快照；前端不编造状态。
