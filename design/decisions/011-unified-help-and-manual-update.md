# 011 · 设置 + 帮助分工与手动检查更新

- **状态**：confirmed（入口分工 2026-11-02 修订，代码未落地）；技术验证与用户视觉验收分开登记。
- **日期**：2026-10-25（2026-11-02 修订入口分工）。

## 问题

旧界面「说明」与「更多」都提供重看引导，内容少却让用户在两个模态间查找；大块浅黄色强调区
也偏离了主界面站牌与时刻表的视觉。现有「查看发布页」只打开链接，不进行版本比较。
2026-11-02 新工作台把顶栏收敛为刷新、设置、帮助后，需要明确哪个入口放恢复动作、哪个入口只做解释。

## 用户确认与采用方案

顶栏分「设置」与「帮助」两个入口，各司其职：

- **设置**放需要操作的恢复动作：高级功能（手机访问、验证码识别）、登录（保存的账号与自动登录）、
  程序（关闭窗口、版本与更新、本机数据、条款与隐私）。
- **帮助**只做解释：三步快速帮助、键盘快捷键、重看五步引导、查看条款全文，不直接修改设置。

版本与更新放在设置 → 程序的「版本与更新」分组，`bootstrap.version` 仍是唯一版本显示位；
检查结果就地展开，不跳页、不弹窗。

手动检查固定仓库最新正式 Release，比较三段整数版本；请求有限超时、单飞、可恢复。
启动和打开设置不联网查版本，不带任何学校凭证，不自动下载或安装。
当前 1.1.0 尚未发布，线上基线实查仍为 1.0.2；同一候选继续沿用 1.1.0。

更新七态的状态集与判定沿用 [UI_SPEC §5.18](../../docs/UI_SPEC.md)，不变；变的只有按钮的位置和节奏
（新工作台设计第 9.2 节，原型 Update* 场景）：
- 每个状态只留一个推进动作，固定放在「版本与更新」标题行右侧；
- 状态自己变化后，新出现的按钮先停 0.8 秒才可点，防止连点误触；
- 计划运行中校验通过时先提醒，按钮改为「仍然启动安装程序」；
- 启动安装程序后给「关闭本工具…」，接到关闭窗口对话框。

## 用户可见行为

| 情况 | 结果 |
|---|---|
| 想了解用法 | 帮助里看到三步快速帮助，或点「重看引导」 |
| 想改手机访问、验证码识别、登录、关窗或数据目录 | 打开设置，按组操作；组件一键下载安装，失败才导入 |
| 想查版本 | 设置 → 程序 → 版本与更新，点检查；结果显示版本比较和检查时间 |
| 正式版高于本机 | 提示发现新版，就地「下载并安装」；仍可在发布页手动选择独立 EXE 或完整 ZIP |
| 本机候选高于正式版 | 明确预览状态和正式版号，不劝降级、不编造已发布状态 |
| 查询失败 | 局部说明原因并恢复重试按钮，不污染登录或报名结果 |
| 报名运行中 | 设置与帮助都可用；只禁用重看引导，查版本不打断计划 |
| 关闭再打开设置/F5 | 沿用本实例内存里的结果或在途请求，不自动再查一次 |

## 已知限制

检查依赖 GitHub 可达性与其限流策略；失败可直接查看发布页。只认正式三段版本，不自动切换到预发布渠道。
结果仅代表显示时间的那次查询，不持续监控。新设置抽屉与帮助页尚未实现，当前代码仍是「更多 + 说明」。
学校真实报名和用户视觉接受仍需要单独确认。

## 变更方式

改界面同步 `local/ui/views/settings.js`、`local/ui/views/help.js`、`local/ui/views/update.js` 与本规范；
改版本比较同步 `local/update_check.py` 和对应单测；改桥接同步 `local/app.py`、UI 事件与测试；
正式发布继续走既有用户授权和发行门禁。

## 2026-11-02 修订（设置 + 帮助分工）

上一节「帮助仍是唯一入口」是 2026-10-26 的历史结论，已被本节取代：

- 顶栏从「说明 + 更多」改为「设置 + 帮助」。设置放需要动手的恢复动作，帮助只做解释。
- 版本与更新从帮助移到设置 → 程序；七态的判定、检查逻辑、超时、单飞、版本比较规则与 1.1.0 候选都不变，
  推进按钮改到标题行右侧并加 0.8 秒防误点。
- 高级功能（手机访问、验证码识别）与登录、关闭窗口、本机数据、条款与隐私都归设置；
  帮助保留三步快速帮助、快捷键、重看五步引导与查看条款。
- 重看引导仍在计划运行时禁用并说明原因。
