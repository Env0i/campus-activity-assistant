# 本机版新工作台与手机页重做设计

状态：已获用户批准，2026-11-02（UI 原型讨论收尾）。2026-11-03 按[架构方案](2026-11-03-architecture-revision-design.md)回填了第 13 节等的四个结论，原型同步到版本 32。

- 可操作原型：claude.ai 私有画布（只有仓库所有者能打开）<https://claude.ai/artifact/7Yn6ftvGqoH1PS2K1qS1PS>，版本 32。
- 本机原型：[design/prototype/workbench-2026-11/](../../../design/prototype/workbench-2026-11/)，含全部源码、83 张画板和本机查看器，双击 `打开原型.bat` 就能在本机浏览器里操作（画布运行时只留在本机，不进仓库）。原型只用假数据，不连学校、不连网。
- 实现计划：`20261102-workbench-ui`（Plan Protocol 2.2.1，存放在被忽略的 `.claude/plans/`）。**暂缓执行**：架构结论已回填，计划细节已按结论修补（2026-11-03），等用户放行。

## 1. 为什么要重做

旧界面是一块“大屏 + 时刻表”，大屏同时承担引导、草稿、运行和结果四件事。同一块区域在不同阶段换含义，导致状态混乱；窗口一矮，大屏又先把时刻表挤没。帮助入口里塞了高级功能、更新、条款，用户找不到。

新方向：**时刻表在左，计划栏在右，各管一件事**。时刻表只负责“有哪些活动、勾选哪些”；计划栏只负责“这次计划现在处于哪一步、下一步做什么”。顶栏只放状态和三个入口：刷新、设置、帮助。

## 2. 目标与非目标

目标：

1. 状态统一：同一件事在电脑、手机、顶栏、计划栏的说法和颜色一致。
2. 每个状态只给一个推进动作，按钮下面写清还差什么。
3. 完整、精美、好操作。精致度以现有 `local/ui` 为基线，LED 点阵、“现在”线、大号时刻、状态标签、运行路线图都保留。
4. 窄窗口、矮窗口、150% 缩放都能用，关键操作不被挤掉。

非目标：

- 不改报名调度、重试策略、登录态机制、学校接口契约（架构讨论另行决定的除外）。
- 不做多账号、批量占位、代他人报名。
- 不重新设计字体和配色（第 11 节只做一处收紧）。
- 不引入新依赖，仍是纯静态 `index.html` + `styles.css` + 普通脚本。

## 3. 整体布局

```
┌ 顶栏：品牌 │ 北京时间  登录胶囊  手机标识 │ 刷新  设置  帮助 ┐
├ 横幅（最多一条，按优先级）                                   ┤
├ 时刻表（搜索、筛选、按天分组、现在线） │ 计划栏（点阵屏 + 当前阶段）┤
├ 运行记录（收起一行，可展开）                                   ┘
```

窗口分档（按 CSS 视口，150% 缩放时 1120×800 的窗口约等于 746×512）：

| 档位 | 条件 | 布局 |
|---|---|---|
| 宽 | 宽 ≥ 1040 | 时刻表 + 25rem 计划栏并排 |
| 中 | 720–1039 | 只显示时刻表，底部一条“计划条”（已选几场 + 查看计划 + 开始）；点“查看计划”计划栏占满主区，左上“返回列表”。顶栏刷新、设置、帮助只留图标，悬停有文字提示 |
| 窄 | < 720 | 同“中”，再收起“北京时间”字样、搜索框缩短；详情卡改为铺满宽度 |
| 矮 | 高 < 660 | 点阵屏缩小到 13rem 宽，计划栏内部可滚动，主按钮固定在底部 |

计划栏在单栏（中、窄）时点阵屏限宽 22rem，不铺满。

中、窄档的计划条有开始前提醒时，不给“开始”，只给“查看计划”，并写“有 N 条提醒，开始前先看一眼”。

原型场景：`Main`、`Medium`、`MediumRun`、`Short`、`Narrow`、`NarrowPop`、`NarrowWarn`。

## 4. 顶栏

- **北京时间**：沿用决策 012 的五态（已校准 / 校准中 / 使用上次校准结果 / 待校准 / 演示时间）。“使用上次校准结果”可以照常开始报名，只在计划栏提醒，倒计时照常走。
- **登录胶囊**：已登录（宽窗口旁边小字写上次校验时刻，如“14:20 校验”）/ 自动登录中 / 登录已失效 / 暂时无法确认 / 没有登录 / 正在登录 / 等同意条款。不显示剩余时间，也没有“临近失效”：学校不公布有效期，工具不估算（架构方案 4.5）。
- **手机标识**：只在手机访问开启时出现（等手机连接 / 手机已连接 / 通道断开）。

三个都是按钮，交互一致：

- 鼠标悬停约 0.2 秒弹出详情卡，移开消失；点击固定，再点或按 Esc 关闭。
- 卡片贴在按钮下方，深色头部：时间卡用点阵显示时间，登录卡用大号“登录有效”加上次校验时刻，手机卡显示连接状态；下面是明细行、一句说明和动作按钮（重新校准 / 刷新、重新登录 / 管理手机访问）。登录卡的明细写明“有效多久：学校不公布，工具不估算”和“别处登录会让这里失效”。
- 窄档卡片铺满宽度、去掉指示箭头。

原型场景：`PopClock`、`PopLogin`、`PopDown`、`PopPhone`、`ClockHold`。

## 5. 时刻表

- 按开放时间排、按天分组（正在开放 / 今天 / 明天 / 后天 / N 天后 / 待公布），“现在”线把已开放和未开放分开。
- 每行：勾选框、开放时刻（大号数字）、活动名、报名模式标签、举办时间、签到签退、地点、距开放。
- 活动名和地点最多两行，超出截断，悬停看全文。
- 举办时间重叠的行写明和哪一场冲突；与已报名活动冲突的不能勾选。
- 列表上方写“N / M 场”和新鲜度（刚刚更新 / N 分钟前更新，超过 10 分钟变警告色）。列表没加载时不显示场数，也不显示新鲜度。
- 电脑睡眠错过开放的场次标“错过了”，可以重新勾选。

空态分四种，不能混用：

| 情况 | 标题 | 动作 |
|---|---|---|
| 筛选后为空 | 没有符合条件的活动 | 清除筛选 |
| 学校返回 0 场 | 学校当前没有返回活动（写明“这不是登录问题”） | 刷新 |
| 列表没加载（未登录、失效、断网、条款未同意） | 写原因 | 该原因对应的一个动作 |
| 程序组件缺失 | 活动列表没加载 | 不放第二个按钮，看顶部横幅 |

原型场景：`Main`、`LongName`、`ZeroAct`、`Slept`、`Broken`。

## 6. 计划栏

计划栏上半是点阵屏（倒计时或结果数字），下半是当前阶段的内容和一个主按钮。

| 阶段 | 点阵屏 | 内容 | 主动作 |
|---|---|---|---|
| 草稿·没选 | 暗屏“暂时没有目标” | 还没选活动 | 开始（禁用，下面写“还差一步：先在时刻表勾选活动”） |
| 草稿·已选 | 下一批开放倒计时 | 按批次列出已选场次，可逐场移除；尝试时长和最多提交次数 | 开始报名计划 |
| 草稿·有提醒 | 同上 | 开始前提醒列表（见下） | 仍然开始报名计划 |
| 等开放 | 琥珀倒计时 | 运行路线图（本次启动 → 准备好提交 → 原定开放 → 本次尝试截止 → 向学校核对）+ 每场卡片；改用页面点击的场次，第二步叫“活动页已打开” | 修改计划、停止计划 |
| 修改中 | 琥珀倒计时 | “计划已暂停，改完要重新开始”；可增删场次 | 重新开始计划、放弃修改 |
| 提交中 | 红色倒计时到本次尝试截止 | 路线图 + 每场提交次数和最近回应 | 停止计划（修改计划禁用，写原因） |
| 结果 | 已报名 / 名额已满 / 未成功 / 待核对 等大数字，只显示不为 0 的 | 每场结论；待核对的场次带“打开活动页”“刷新核对” | 重新选择未成功的场次（有可重选的才显示）、完成回到活动列表 |

规则：

- **修改计划**（已定）：等开放时可用，复用停止和重选，不改报名调度；提交中或开放前 100 秒内不可用；修改期间明确提示计划已暂停。
- **开始前提醒**只提醒不拦，列在计划栏里：断网；北京时间在用上次校准结果；最晚一场要等 1 小时以上、又没开全自动登录（1 小时由用户 2026-11-03 确认；学校不公布有效期，这个数是判断，不是测出来的）（没保存账号带“去保存”，没装验证码识别带“去安装”，写明开放前 100 秒内失效的那场会直接结束）；尝试时长选“直到报名截止”但有场次没给截止时间（只会尝试 2 分钟）；有场次 24 小时以后才开放（按最晚一场算，旧界面按最早一场，有意改的）。
- **运行中登录失效**（架构方案 4.3，电脑和手机同一套）：
  - 等开放、离开放还有 100 秒以上：计划不停。能自动登录就自动登录，胶囊显示“自动登录中…”，计划栏一行琥珀说明，不用动手，没有横幅。不能自动登录的，计划栏写“HH:MM:SS 前重新登录，计划照常继续；来不及的话，HH:MM:SS 开放的那批会以‘登录失效’结束”，旁边“重新登录”。
  - 开放前 100 秒内和提交中：只做自动登录（提交中最多约 20 秒，成功后接着提交）。不能自动登录的场次以“登录失效”结束；这时点“重新登录”只弹出“现在来不及重新登录”说明原因。
  - 重新登录成功后，运行记录和手机页都写“报名计划照常继续”。
- **提交方式**（架构方案 3.1）：每场准备好以后，卡片写明“直接提交，不经过活动页”，或琥珀色的“改用页面点击：原因。活动页已提前打开”；改用点击同时写进运行记录。尝试设置里的“显示浏览器窗口”改名“改用页面点击时显示浏览器”。
- **结束结论**（架构方案 3.3）：报名成功（写明结束时向学校核对过）；名额已满（中性色，写明不是工具出错，不放回“重新选择未成功的场次”）；时间冲突、报名已截止、活动不存在、登录失效、本机时钟有问题（红色“报名未成功”加原因）；待核对。全部场次都是名额已满时，标题写“这次没报上：名额满了”，不用红色。
- **待核对**：每场结束时工具已用 `getJoinInfo` 向学校核对一次，核对也没拿到结果才是待核对。“刷新核对”这一轮先刷新活动列表、看该场 `signed`（单场 `getJoinInfo` 入口还没有，2026-11-03 拆计划时定，见 UI-B 计划 code-arch-followups）；学校列表显示已报名就改成成功，还没显示时提示列表可能有延迟、去活动页看一眼；工具不会自动重发。
- **计划来源**：从手机开始的计划，计划栏底部写“这个计划是从手机开始的，在电脑和手机上都能看进度、停止”。
- **后台结束**：窗口最小化或隐藏时计划结束，发系统通知（N 场成功、N 场待核对、N 场名额已满、N 场没成功），点通知回到窗口。

横幅一次只显示一条，优先级：程序组件缺失 > 条款未同意 > 断网 > 电脑刚睡眠过 > 登录问题 > 北京时间问题。

原型场景：`Main`、`Running`、`Waiting`、`Editing`、`Result`、`PreWarn`、`NetOff`、`RunExpired`、`RunAuto`、`RunClick`、`RunPhone`、`ToastMin`、`LoginShort`。

## 7. 新手引导

取代决策 009 的六步和启动时机：

- 登录成功、活动列表加载后才自动开始；条款没同意时不开始。
- 五步：这是活动时刻表 → 勾选想报的活动（这一步可以真的点一行）→ 核对计划，再点开始 → 开始以后看这里 → 出问题先看顶部。
- 除勾选那步，其余步骤背景不可点；引导不替用户做任何动作。
- 引导内容版本号要升，老用户会再看一次；帮助里可以重看。

原型场景：`TourTable`、`TourPick`、`TourRun`。

## 8. 设置抽屉

顶栏“设置”打开右侧抽屉。顶部固定一排分组按钮：高级功能、登录、程序，点一下跳到对应分组。

### 8.1 高级功能（可选，用到时点一下就装）

- **手机访问**：
  - 流程：未安装时标题行右侧“下载并安装”→ 选通道（Tailscale 长期地址 / Cloudflare 临时地址）→ 开启手机访问 → 显示二维码和点阵配对码（5 分钟有效、只能用一次）→ 配对成功后收起配对码 → 关闭要确认。
  - 手机配对成功、但电脑没保存账号密码时，提示“出门前建议保存账号密码”。
  - 通道规则沿用 [2026-10-31 手机访问通道设计](2026-10-31-phone-access-channel-design.md)，只是入口从“帮助 → 高级功能”搬到“设置 → 高级功能”。
- **验证码识别**：未安装时标题行右侧一个“下载并安装”，自动下载、校验、启用，可取消。下载失败才露出“导入已下载的组件包”作为后备，导入仍当场自检；选错组件包要说清选的是哪个。

### 8.2 登录

**登录恢复**：

- 可以保存账号密码，也可以只用一次（只在本次运行内存里）。
- 账号只显示打码（前两位加后两位），清除要确认。
- 写明“失效后自动登录”是否生效：没账号 → 未启用；有账号没识别 → 只需你输验证码；都有 → 已启用（报名计划等开放或提交时也一样）。前两种要写明：报名计划开放前 100 秒内失效的场次会直接结束。
- 学校说密码错时，自动登录暂停，直到更新密码。

### 8.3 程序

- **关闭窗口时**：每次询问 / 最小化 / 隐藏到后台 / 直接退出。
- **版本与更新**：见第 9.2 节。
- **本机数据**：打开数据目录。
- **条款与隐私**：显示同意了哪一版、什么时间；查看条款；撤回同意。

原型场景：`Settings`、`PhoneSetup`、`PhoneTs`、`PhoneWait`、`PhoneLinked`、`CompLive`、`CompOk`、`CompFail`、`CompWrong`、`CredForm`、`CredSaved`。

## 9. 对话框

### 9.1 关闭窗口

- 先列出正在运行的东西（报名计划、手机访问），再给三个出口：最小化到任务栏（默认焦点，计划运行时标“推荐”）、隐藏到后台、退出程序。
- 计划运行中选退出，要二次确认。
- 记住的“直接退出”在计划运行时仍会询问。
- 没有托盘、且手机没连时，“隐藏到后台”不可用（隐藏后叫不回来）。

原型场景：`CloseLive`、`CloseAsk`、`CloseConfirm`、`CloseIdle`、`CloseHidden`。

### 9.2 更新

- 按 UI_SPEC §5.18 的七态，每步只留一个推进动作，固定放在“版本与更新”标题行右侧（用户 2026-11-02 要求挪到这里）。
- 状态自己变化后，新按钮先停 0.8 秒防误点。
- 计划运行中校验通过时提醒，按钮改为“仍然启动安装程序”。
- 启动安装程序后给“关闭本工具…”，接到关闭窗口对话框。

原型场景：`UpdateLive`、`UpdateAvail`、`UpdateDown`、`UpdateReady`、`UpdateFail`。

### 9.3 重新登录（电脑和手机同一套规则）

按“电脑上有没有账号密码 × 有没有验证码识别”分四种：

| 账号密码 | 验证码识别 | 点“重新登录”后 |
|---|---|---|
| 有 | 有 | 确认后自动登录一次；登录失效时也自己登录 |
| 有 | 无 | 账号密码由电脑填，你只输验证码 |
| 无 | 有 | 输账号和密码，验证码由电脑认 |
| 无 | 无 | 账号、密码、验证码都输 |

- 验证码认错连续 3 次才转人工输入。
- 学校说密码错，一次就停、不重试，自动登录暂停到更新密码。
- 断网不算失败。
- 手机上允许输账号密码：默认不保存（只在本次运行内存里），勾选后才保存到电脑。
- 登录时工具会替你勾选学校登录页上“我已阅读并同意《隐私协议》”。在账号密码表单、手机重新登录表单和自动登录确认里各写一句，并写进条款；不额外加勾选框。
- 登录失效可推飞书：只在填了机器人地址时推，不带账号。
- 仍可改用浏览器登录。
- 报名计划运行中也能重新登录，时机限制见第 6 节“运行中登录失效”。

原型场景：`Relogin`、`RlCap`、`RlConfirm`、`RlBad`、`PhoneCaptcha`、`PhoneAuto`、`PhoneRelAll`、`PhoneRelAcct`、`PhoneRelConfirm`、`PhoneRelBad`。

### 9.4 条款

- 完整条款三个页签（用户协议、隐私政策、开源许可），左侧章节目录。
- 升版时先弹“使用条款更新了”列出改动，再可看全文；正文里标“本版新增”。
- 首次使用摘要包括自动登录和联网对象。

**未同意的效果**（首次拒绝、新版没同意、撤回都算）：

- 电脑和手机上都停用：登录、登录检查、自动登录、刷新活动、开始计划。
- 登录胶囊显示“等同意条款”。
- 有缓存的活动列表只读显示，标明可能过时。
- 帮助、设置、查看条款、校时、检查更新、组件安装照常可用。
- 已保存的账号密码和登录信息保留，不删。
- 升版或撤回后重新同意，立即检查登录并刷新活动。

**撤回**：设置里可以撤回同意，需确认；计划运行中不可撤回。

离线演示只能用命令行 `--demo` 启动，界面没有入口，所以条款里不写“可以用离线演示”。

**正文**：按架构方案第 8 节的 r4 披露清单起草（原型版本号 `2026-11-03-r4`，日期按正式发布那天定），措辞由用户过一遍。升版改动摘要列 6 条：直接调用报名接口并取临时密钥、列表详情核对也直连、自动登录代勾协议或完全不经过登录页、会让别处登录失效、写明找到的学校规则且不声称合规、新增的手机重新登录和组件和飞书提醒。候补那条等候补开工时再加，到时再升一版。

原型场景：`FirstUse`、`TermsUpdate`、`TermsDoc`、`TermsPrivacy`、`TermsOff`、`TermsWithdraw`、`PhoneTerms`。

## 10. 手机页

- **配对**：输入电脑上显示的 6 位配对码，输入框是点阵屏样式；输错太多次锁定并显示倒计时。
- **首页**：
  - 点阵屏显示下一批开放倒计时和北京时间。
  - 页签：可报名 / 已报名 / 全部。
  - 勾选后底部出现“核对并开始”。
- **核对计划**：底部弹层列出已选场次、尝试时长、最多提交次数，以及和电脑同样的开始前提醒；有提醒时按钮写“仍然开始报名计划”。
- **运行中、结果**：和电脑同一套阶段和说法。手机上只能停止计划；要修改计划，回电脑上点“修改计划”。
- **连不上电脑**：顶部红条说明“确认电脑开着、程序没退出”，提供重试；电脑上的计划不受影响。
- **重新登录**：同第 9.3 节四种情况，电脑正在自动登录时手机只显示进度。计划等开放时也能在手机上重新登录；开放前 100 秒内和提交中只说明来不及。
- **电脑没同意条款**：手机停在缓存，不能开始，也不能重新登录。

原型场景：`PhoneApp`、`PhonePick`、`PhoneReview`、`PhoneReviewWarn`、`PhoneRun`、`PhoneResult`、`PhoneLock`、`PhoneOffline`、`PhoneCheck`、`PhoneExpired`、`PhoneTerms`。

## 11. 视觉、键盘与用词

**字体配色**：沿用旧界面那套，不重新设计。唯一收紧：

**Logo**：入场券（2026-11-02 选定），资产和规则见 [design/brand/](../../../design/brand/README.md)。原型版本 32 起，顶栏、标题栏、任务栏、托盘、系统通知和手机页都换成了小尺寸版。

**键盘**：

- F5 刷新，Ctrl+F 搜索。
- Esc 逐层关闭：详情卡 → 对话框 → 抽屉。
- 帮助里列出快捷键。

**用词**：

| 用这个 | 不用这个 | 指什么 |
|---|---|---|
| 重新登录 | 重登 | 用户主动登录这个动作 |
| 自动登录 | 自动重登、电脑上自动恢复 | 失效后工具自己登录 |
| 刷新 | 刷新状态 | 顶栏按钮 |
| 报名计划 | 任务、抢报 | 一次选好的场次集合 |
| 待核对 | 未知、处理中 | 提交了但没拿到确定回应，结束时核对也没结果 |
| 直接提交 | 直发 | 不经过学校页面，直接调用报名接口 |
| 页面点击 | 点击兜底 | 打开活动页点“立即报名”，只在直接提交用不了时用 |
| 名额已满 | 没抢到 | 学校说报名人数已满，本场结束，不算工具失败 |

## 13. 待定项与依赖

架构讨论的四个结论（2026-11-03，[架构方案](2026-11-03-architecture-revision-design.md)第 13 节），已画进原型版本 32：

1. **计划等开放时能原地重新登录**，计划不停。开放前 100 秒内和提交中只做自动登录，做不了的场次以“登录失效”结束。界面规则见第 6 节。
2. **条款升到 r4**，披露清单见架构方案第 8 节。条款正文文件归架构计划改，本设计只做界面机制和草案（第 9.4 节）。
3. **“刷新核对”用 `getJoinInfo`**，列表的 `signed` 作辅助；每场结束时也用它核对一次。
4. **活动已开始不做专门处理**：316 场里 0 例，不加提示样式、不走单独路径，状态只看报名窗口。

架构方案另外要求、也已画进原型的：每场写明提交方式；名额已满是结束结论；登录只显示上次校验时刻。候补入口等架构方案第 6 节开工再画。

需要后端配合的（本计划内做）：

1. 验证码识别组件包发到 Release；清单解析和下载服务从只认 `phone_control` 改成两种都认。
2. 手机端提交账号密码：默认只放本次运行内存，勾选后才保存。
3. 撤回条款同意。
4. 登录失效推飞书（复用现有机器人地址配置）。
5. 后台结束的系统通知（不引入新依赖）。
6. 计划来源字段。

依赖架构计划的（本计划只消费，不实现）：

1. 每场的提交方式和改用点击的原因（架构方案 3.1）。
2. 按回包分类表给出的结束结论，和结束时的 `getJoinInfo` 核对结果（3.3、3.5）。
3. 计划运行中重新登录后，worker 读到新登录态继续（4.3）。
4. 上次校验时刻，以及去掉 17.5 小时常量（4.5）。
5. 条款 r4 正文和 `TERMS_VERSION`（第 8 节）。

需要用户确认的：

1. 验证码是否区分大小写。
2. 条款措辞由用户或法务过一遍。

仍缺的材料（不影响界面，先按“没见过的回包”处理）：真实 404/429、性别不符时的回包、同学首次使用的卡点。
