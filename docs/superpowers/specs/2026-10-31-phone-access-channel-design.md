# 手机访问通道与组件分发设计

状态：已获用户批准，2026-10-31

2026-11-02 起入口改为「设置 → 高级功能」，见[新工作台设计](2026-11-02-workbench-ui-redesign-design.md)与[决策 014](../../../design/decisions/014-workbench-ui.md)；下文「帮助 → 高级功能」按此理解，其余内容不变。

## 目标

让用户在“帮助 → 高级功能 → 手机访问”里完成一次清晰的安装与启用流程，并能明确区分两条远程通道：

- Tailscale 是默认的长期通道。
- Cloudflare Quick Tunnel 是用户明确点击后才开启的临时/应急通道。

手机控制组件是可选高级功能。组件没有安装时，入口必须可见；普通用户不需要寻找 `cloudflared.exe`、填写路径、解压 ZIP 或执行自检。

## 已拍板的边界

1. 不增加局域网通道，也不增加新的顶级导航入口。
2. 同一时间只运行一条远程通道。
3. Tailscale 设备信任在程序重启和电脑重启后保留；用户登录 Windows 并启动程序后不重新扫码。
4. 本轮不要求 Windows 尚未登录时仍能访问，不做 Tailscale 无人值守后台服务。
5. Cloudflare 每次启动都视为新的临时通道；地址、二维码和配对会话与本次进程绑定。停止、异常退出或程序结束后，旧地址和旧二维码立即失效。
6. 不自动从 Tailscale 切换到 Cloudflare。Cloudflare 只能由用户明确选择并开启。
7. `phone_control` 组件包是 Cloudflare 依赖的唯一受管来源，内部携带匹配版本的 `cloudflared.exe`、manifest 和校验信息；不从 PATH、程序目录或任意同名文件回退。
8. 组件安装、下载和升级都必须由用户主动触发；不后台安装、不自动升级。
9. 组件下载使用项目已有的 Release/HTTPS 下载和系统/环境代理能力；学校接口仍然直连；不增加代理编辑界面。
10. 组件移除不会影响 Tailscale；移除正在使用的手机控制组件前必须先停止手机访问并清除当前手机会话。

## 方案选择

### 组件获取：项目 Release 组件包（采用）

正式 Release 增加独立的 `phone_control` Windows x64 组件包。它不是主程序安装器的一部分，用户点击安装后才下载到受管数据目录。源码版与安装版使用同一份组件资产和校验规则。

组件包必须包含：

- `manifest.json`：功能名、目标平台、组件版本、应用兼容版本、文件大小和 SHA-256。
- `bin/cloudflared.exe`：项目固定的匹配版本。
- 现有 `phone_control` 运行所需的其他文件。

下载先写 `.part` 临时文件，完成大小和 SHA-256 校验后原子替换，再调用现有组件安装逻辑。失败、取消、大小不符、哈希不符或版本不符时删除临时文件，并保留原有已安装组件。

### 不采用的方案

- 普通用户手动选择 `cloudflared.exe`：把来源判断、路径管理和版本匹配交给用户，正是本次 2.2 真机验收失败的原因。
- 普通用户手动导入任意 ZIP：保留为高级维护入口，但不作为首次安装入口。
- Cloudflare Named Tunnel：需要账号、域名和长期配置，与“临时/应急通道”定位冲突。
- Tailscale Funnel：会把默认长期通道公开化，破坏两条通道的安全语义。

## 状态模型

实现中必须分别维护三层状态，不能再用一个 `ready` 同时代表它们：

### 手机控制能力

`missing`、`checking`、`available`、`confirm`、`downloading`、`verifying`、`ready`、`failed`、`removing`。

### 远程通道

- Tailscale：`not_installed`、`not_logged_in`、`ready`、`starting`、`running`、`failed`。
- Cloudflare：`missing_component`、`ready`、`starting`、`running`、`exited`、`failed`。

### 手机会话

`unpaired`、`paired`、`expired`。Cloudflare 的会话必须绑定当前临时地址；Tailscale 的设备信任可以跨程序/电脑重启恢复。

## 用户流程

### 首次安装

1. 用户打开帮助里的手机访问区。
2. “安装手机控制”按钮始终显示，不再由 `phoneReady` 隐藏。
3. 用户点击后看到组件版本、大小、来源和用途，点击一次“确认安装”。
4. 程序下载组件、显示进度、校验 manifest/SHA-256/`cloudflared --version`，然后安装。
5. 安装成功后回到手机访问卡，主按钮变为“开启手机访问”；不自动公开通道。
6. 下载失败显示可读原因和“重试”；取消只删除临时文件；网络不可用不影响 Tailscale。

### Tailscale

1. 默认选择 Tailscale。
2. 未安装或未登录时，显示“安装/登录 Tailscale”和“重新检查”；程序不代替用户安装外部客户端。
3. Tailscale 可用时，用户点击“开启手机访问”。
4. 成功后展示稳定地址、二维码和一次性配对码。
5. 用户扫码并输入配对码后，手机端进入控制台。
6. 程序重启或电脑重启后，用户登录 Windows、程序恢复运行即可沿用设备信任，不重新扫码。

### Cloudflare

1. 用户主动选择“Cloudflare · 临时”。
2. 没有受管组件时，主按钮显示“安装组件”；安装成功后显示“开启 Cloudflare 临时通道”。
3. 启动中显示“正在建立临时通道”，期间禁用重复点击。
4. 只有拿到新地址后才显示二维码、地址和配对码。
5. 页面明确写出“关闭后地址失效；重新开启后需要重新扫码”。
6. 停止或异常退出时立即清空地址、二维码和配对入口，状态变为“临时通道已失效”，提供“重新开启”。
7. 程序重启后不自动开启 Cloudflare。

## UI 设计

入口继续使用现有帮助弹窗和 `help-advanced` 区域，沿用项目已有的 `--hall`、`--paper`、`--ink`、`--blue`、线框按钮和紧凑状态标签。不新增全局导航、不引入渐变和新的卡片体系。

```text
手机访问                                      [未安装 / 已就绪 / 已开启]
手机控制电脑报名、查看活动、续登录

手机控制组件        未安装                    [安装手机控制]

远程通道            [Tailscale · 长期 ▼]
通道状态            已就绪                    [开启手机访问]
```

选择 Cloudflare 且组件未安装时：

```text
远程通道            [Cloudflare · 临时 ▼]
通道状态            需要 Cloudflare 组件      [安装组件]
关闭后地址会失效；重新开启后需要重新扫码。
```

通道开启后统一显示地址、复制按钮、配对码和二维码。保留已确认的书签提示；Cloudflare 额外说明重新开启后需要更新地址。状态消息使用现有 `help-status` 和 `data-tone` 体系，错误必须说明下一步动作。

组件对话框保留给高级维护：显示已安装版本、校验状态、移除按钮，以及折叠的“从本机导入完整组件包”。首次使用不显示路径输入框、裸 `cloudflared.exe` 选择器或“自检”二级按钮。

## 安全与生命周期

- Tailscale 的 tailnet 访问控制和应用配对同时生效；不能因为处于 tailnet 就省略应用配对。
- Cloudflare 地址是公开可访问的临时地址；未配对前不得返回活动、登录状态、凭据或写操作结果。
- 配对码、会话 Cookie、CSRF 值和凭据不能进入地址、二维码内容、日志或普通 UI 文案。
- Cloudflare 隧道退出必须在下一次状态读取中被识别，旧地址和 QR 必须同时清除，不能被第二次 `status()` 降级为“可用”。
- 不自动故障转移到 Cloudflare，避免 Tailscale 故障时意外公开服务。
- 组件被替换、哈希不符、版本不匹配或 PATH 中存在同名程序时，都不能启动 Cloudflare。

## 验收标准

1. 未安装手机控制组件时，帮助页入口可见，且不需要用户猜测入口。
2. 用户可通过“确认安装 → 下载 → 校验 → 安装”完成组件安装，不需要选择路径或执行自检。
3. 组件下载失败、取消、大小不符、哈希不符时，不破坏旧组件，不污染临时文件。
4. Tailscale 首次启用、扫码、配对、重启后登录 Windows 再访问全链路通过。
5. Cloudflare 首次启用、安装组件、启动、扫码、配对、停止、重启后重新开启并重新扫码全链路通过。
6. Cloudflare 异常退出后旧地址和旧 QR 消失，不能继续访问；Tailscale 不受影响。
7. Tailscale 失败不会自动启动 Cloudflare。
8. 真实手机上可看见长期/临时标签、安装进度、失败原因、地址、复制按钮、QR、配对码和书签提示。
9. 组件版本/哈希、PATH 同名程序、来源错误和跨功能组件混装的自动化测试通过。

## 不在本轮

- Windows 尚未登录时的手机访问。
- Cloudflare 账号登录、Zero Trust Access、Named Tunnel、固定域名。
- 局域网直连。
- ddddocr 自动续登录的产品流程重做。
